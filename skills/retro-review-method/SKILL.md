# 自我复盘方法论

定期（每日/每任务周期）执行结构化复盘，核心目标：**清账 > 新增**，防止行动清单变成许愿池。

## 四步走

### 1. 旧账对账（先还债再干活）
- 取上次复盘的行动清单，逐条标注：✅ 兑现 / ⚠️ 半兑现（附阻塞原因）/ ❌ 未兑现。
- **每条必须有证据**（落盘文件、会话记录、验证结果），没有证据视为未兑现，不许凭印象打勾。
- 有期限的挂账（如服务下线核查）单独标出剩余时间，临近优先。
- 统计兑现率，连续走低说明问题在优先级管理而非记忆，直接进入第 4 步收敛。

### 2. 会话扫描（只看事实，不看感觉）
逐个会话问四件事：
- **交付了吗**：产出物是否验过（链接验 200、文件验存在、尺寸验实际值）？
- **有没有断在半截**：用户最后的请求是否有下文？（常见欠账：用户补一句「按A做」「换风格吧」之后会话结束）——这是最容易漏的债。
- **边界/透明度守住没**：拒了什么、理由是否表达清楚、是否尊重用户决定权。
- **自我纠错发生了吗**：当场认错值得记下来强化；同类错犯第二次要升级为规则（见第 3 步）。

### 3. 经验提炼（把错误变成规则）
- **能力性结论必须先查样本**：下「通道不支持 X」「系统不具备 Y」这类结论前，先翻一遍同类产物/配置目录再定论；样本 <3 不得下断言。
- **执行到位 ≠ 沉淀到位**：好实践（如「生成类链接先验 HTTP 200+真实内容」）必须写进正式约定文档，只在会话里做不算数。
- **「透传成功」≠「质量合格」**：连通性验证和质量抽检是两件事，报告里注明做到哪一层。
- 诚实记录限制（如模型不吃某宽高比）而不是掩饰。

### 4. 行动清单收敛（刻意少挂）
- 新行动必须带 `kind`（fix/track/ask）和 `due`：
  - **fix**：今天能做完的，当场做完或列明确步骤；
  - **track**：等外部条件（如队列恢复），写清触发条件和备好的弹药；
  - **ask**：旧账去向不明时，列入「向用户确认是否仍要做」，明确去留而不是无限挂着。
- 新增条数 ≤ 当日已兑现数 +1；连续两天只清一条旧账时，强制先 ask 清债再接新活。
- 半兑现且阻塞的项，要么写明需要用户提供什么，要么升级为 ask，不许静默挂着。

## 坑
- 不要把「执行过」当成「已固化」——区分做一次和写成规则。
- 不要漏扫「会话尾巴」：用户最后一句没有回应的请求是最常见的隐形欠账。
- 复盘本身不要写成散文，四段结构固定：旧账对账表 → 会话逐条 → 成长与反思（做对的/要改的）→ 行动 JSON。
