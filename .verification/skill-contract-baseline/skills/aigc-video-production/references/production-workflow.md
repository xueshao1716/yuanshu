# AIGC 视频生产管理工作流

## 目标

把创意事实、资产事实、镜头意图、生成尝试和验收决定分开记录，避免用文件夹名、聊天记录或某个模型的历史记录充当项目真相。

## 十个阶段与退出条件

| 阶段 | 核心产物 | 退出条件 |
|---|---|---|
| `00_brief` | 项目配置、brief | 受众、时长、画幅、硬约束、预算和权利边界明确 |
| `01_story` | 故事圣经 | 世界规则、角色弧光、视觉母题和禁止变化可检查 |
| `02_assets` | 资产表与参考图 | 每个角色、生物、道具、场景和视效都有稳定 ID 与批准版本 |
| `03_scenes` | 场次表 | 场次顺序、地点、时间、故事目标和状态明确 |
| `04_shots` | 镜头表 | 每个镜头有唯一 ID、时长、目的和前后动作接点 |
| `05_prompts` | 版本化提示词 | 主提示词、平台适配层、假设和负面约束分离 |
| `06_generations` | 生成记录 | 每次尝试可回到镜头、提示词版本、模型参数、成本和输出 |
| `07_review` | 选片与连续性记录 | 选择理由、缺陷、连续性和豁免均可追溯 |
| `08_edit` | 时间线与剪辑说明 | 画面、声音、字幕、转场和调色版本明确 |
| `09_delivery` | 交付检查表 | 技术、内容、权利、归档与发布授权均完成 |

## 镜头状态

推荐单向推进：`planned` → `prompt_ready` → `generated` → `reviewed` → `selected` → `locked`。需要返工时记录原因和新版本，不覆盖旧生成或旧选择。

## 单一数据源

- 资产事实只写在 `assets.csv`；提示词引用资产 ID，不重新发明身份。
- 场次顺序与地点只写在 `scenes.csv`。
- 镜头顺序、时长与状态只写在 `shots.csv`。
- 每次模型调用只追加到 `generation-log.csv`。
- 选片决定只追加到 `selection-log.csv`。
- 跨镜头状态写在 `continuity-matrix.csv`。

## 操作成本边界

本地初始化与校验固定为 **0 个网络请求**、**0 次数据库读写**。提示词创作也不自动发起模型调用。只有用户明确要求生成，并给出提供方、次数/预算和授权后，才进入另一个受控生成流程。

## 推荐节奏

- 先锁最少可用资产，再拆镜头。
- 每个镜头只保留一个主要摄影机意图和可在时长内完成的动作。
- 先生成低成本验证镜头，确认身份、动作和空间规则后再扩大批量。
- 每次评审只修改造成失败的字段，保留旧版本和失败原因。
- 交付前运行 `scripts/validate_project.py`，再人工检查画面、声音和权利。
