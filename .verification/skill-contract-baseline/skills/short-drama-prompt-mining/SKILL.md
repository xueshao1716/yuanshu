# AI 短剧提示词挖掘（short-drama-prompt-mining）

一句话：**扒语料 → 打标签 → 结构×均赞交叉 → 提炼成模板**。
核心思路：点赞跟的是成片质量不是文本长度，所以分析单位是"结构形态"，
不是"字数"。

## 流程

### 1. 扒语料（Next.js 站通用打法）
1. 抓首页 HTML，`grep -oE '/_next/static/chunks/[^"]+\.js'` 拿 chunk 清单
2. **必须带浏览器 UA** 下载 chunk，否则整站下成 404 页（file 命令可识别）
   - 路径带 `(common)` 这类括号要先 urlencode
3. 从 chunk 扒 API 基址：`grep -hoE 'https?://api\.[a-z.-]+' *.js`
4. 找公开数据接口：`grep -hoE '"/[a-z0-9/_-]{3,60}"' *.js | sort | uniq -c | sort -rn`
   按频次排序，feed/works/list 类接口先试无鉴权 GET（带 Origin/Referer）
5. 列表接口通常分页；详情接口逐条拉，提示词常在详情而非列表
6. 语料存 JSON 留档：`文档/<平台>提示词库.json`，可读版出 `文档/<平台>提示词库.md`

### 2. 打标签（30 秒出分布）
先建关键词表（类型词 → 正则），再逐条自动归类。一张词表大约 10 类
（玄幻/甜宠/悬疑/喜剧/治愈/历史/科幻/恐怖/校园/卡通…）。一条可跨多类，
去重靠"主类"字段。落盘 `<语料>_打标签.json`。

### 3. 交叉统计（关键动作）
- **结构形态 × 均赞**：一句话型 / 整段描写型 / 时间轴分镜型，各自均赞对比
  ——比看长度更能定位高分写法（Pavo 实测：时间轴 2.5 赞 > 一句话 2.1 > 整段 1.4）
- 镜头词频、风格词频、结尾钩子模式（反转式/定格式）
- 注意幸存者偏差：最高赞可能是超短提示词（点赞跟成片走），短写法的
  正确姿势是"冲突升级链"而非"偷懒少写"

### 4. 沉淀模板
每类挑 2-3 条高赞代表作全文收录，提炼 3 个以内拿来即用模板。
Pavo 实测三大模板：时间轴剧本型 / 爽点密度型 / 沉浸游览型。

## 铁律

1. 点赞分析的是"结构"不是"文采"——分得清 > 写得长
2. 扒站先试公开接口再想登录态；401 别硬试，看列表接口是否够用
3. 每条语料必须留成片链接，提示词离开画面没法验证套路
4. 语料落盘必须 JSON（可再加工）+ MD（可读）双份
