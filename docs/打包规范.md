## 一、四个包

| 包 | 产物命名 | 大小量级 | 说明 |
|---|---|---|---|
| 安装客户端（Android） | `元枢-v<版本>-arm64.apk` | ~28 MB | debug 证书签名，直装；覆盖安装必须同一证书 |

产物统一放：`D:\pi-workspace\安装包\`，并附 `<版本>-SHA256SUMS.txt` 和 `<版本>-安装说明.md`。

## 二、各包怎么打

### 1. Android APK（已验证可打）

```powershell
cd D:\pi-web\android
$env:ANDROID_HOME = "C:\Users\<用户>\AppData\Local\Android\Sdk"
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
.\gradlew.bat assembleDebug --console=plain
# 产物：android\app\build\outputs\apk\debug\app-debug.apk
```

- 版本号在 `android/app/build.gradle`：`versionName` + `versionCode`（格式 `2 21 3 008` → 2213008），**发版前必须同步递增**
- 签名固定用 debug（`未做 release 签名`），换证书会导致覆盖安装失败
- 首次构建 5–10 分钟（需下 gradle 8.14.3），之后增量约 1–2 分钟

### 2. Windows 离线包（缺 NSIS）

需要：`makensis`（NSIS 3.x）。

```powershell
# 安装：winget install NSIS.NSIS   或 官网下载
# 打包脚本：上次手工执行，未固化 —— 见「四、待补」
```

### 3. 桌面客户端（Tauri）（缺工程）

需要：Rust 工具链（本机有 1.96）+ `src-tauri/` 工程目录（**仓库里没有**）。

### 4. Linux 离线包

需要：WSL Ubuntu 24.04（本机有）+ 打包脚本（未固化）。

## 五、常见坑

| 现象 | 原因 |
|---|---|
| 手机点下载没反应 / 提示"请先安装元枢 X 手机客户端" | **APK 太旧，缺 `YuanshuDownloads` 下载桥**；装最新 APK 即可 |
| 覆盖安装失败 | 新旧 APK 签名证书不同（必须都用 debug 证书） |
| Windows 安装弹"未知发布者" | 未做 Authenticode 签名，属预期，选"仍要运行" |
| 离线包启动后模型不可用 | 离线包不带模型权重，首次仍需配置 API |
| 打包后界面是旧的 | 忘了先 `npm run deploy:frontend` 再打包 |

### 双远端推送

```powershell
git push gitee main
git push origin main     # GitHub；单次推送>100MB 会被低速中断，需分批
```

大批量推送时先设置：

```powershell
git config http.postBuffer 524288000
git config http.lowSpeedLimit 0
git config http.lowSpeedTime 999999
```

分批推送：`git push origin <较早提交>:main` 逐段推进。
