# 服务入口拆分第一步：路由注册生命周期

## 问题与范围

2026-09-25 在核查 Claude 的“服务入口过大”建议时发现：
`server.mjs` 在 HTTP 请求回调内部向 `API_ROUTES` 追加工作台、情绪和历史的 4 条路由。
每个通过鉴权并进入 API 分派的请求都会增加 4 个条目，健康探测也经过该分派。
旧条目继续匹配并不意味着没有问题：后续追加的条目和闭包持续占用内存，未匹配请求还需遍历不断增长的表。
这不证明以往所有服务中断均由此引起；本轮没有做历史事故归因。

## 修复

- 新增 `engine/workbench-routes.mjs`，显式注入现有依赖，不在导入时启动任务或读取工作空间。
- 工作台首屏、情绪汇总、历史列表、历史回滚四个接口在依赖创建后、HTTP 服务创建前注册一次。
- 注册完成后冻结路由数组，阻止请求处理期间继续追加。
- 保留中央鉴权、接口路径、方法、缓存 TTL、响应内容以及回滚接口 8MB 请求上限。
- 历史回滚仅迁移注册位置，未重写文件操作与审计逻辑。
- 不触碰聊天/SSE，不启用未完成的 `server-new.mjs` 或 `server/` 草稿。

## 回归证据

`tests/unit/server-route-lifetime.test.mjs` 提取并执行生产 HTTP 回调，使用临时端口和隔离文件夹，
不启动模型、计划任务，也不写真实工作空间。

- 修复前红灯：25 次成功请求后，路由条目从 1 变成 101，断言失败。
- 修复后定向 5/5 通过（3 个路由测试、2 个模块求值顺序测试）。
- 核对中央鉴权 401、错误方法 404、兼容 token 参数，以及缓存 MISS/HIT 的响应一致性。
- 历史回滚使用真实文件处理器：未鉴权不能写；无效 JSON / 越界路径为 400，缺失备份为 404，超过 8MB 为 413；超过 2MB 但低于 8MB 的合法请求可完成回滚并保留原文件备份。
- 全量 `npm run verify` 退出 0：2205/2205 测试通过（约 169 秒），类型检查通过（约 9 秒），隔离构建通过（约 23 秒）。构建仍有已有的大包和插件耗时警告，不据此声称完成性能优化。
- 最终验证 UTC 时间 `2026-09-25T17:44:44.294Z`，输入指纹 `0971554911feae143e0badbee60b15f6d679ae60fd4dc48ff6af8de939bf4b0f`；`createReviewVerification().read()` 重新计算后状态为 `passed`。
- 重启前确认会话、运行中心与定时任务均无活跃执行，通过正规重启脚本加载。8787 唯一监听 PID 从 21840 变为 20116。
- 在线探活、会话列表、工作台汇总、情绪汇总和历史列表均返回 200；除健康检查外，上述接口无令牌时全部返回 401。未在生产执行历史回滚。
- 这次没有前端改动；没有重建线上 `frontend/dist`，没有另打客户端包，也未做手机实机验收。
