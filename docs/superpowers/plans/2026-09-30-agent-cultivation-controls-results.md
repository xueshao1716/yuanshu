# 自主培养控制内核：阶段验收记录

日期：2026-09-30。分支：`feat/agent-cultivation-ecology`。这是第二阶段的内部控制能力交付，不是完整培养产品，也不是线上启用记录。

本轮代码分三次提交：`61de85c0`（可信身份与版本化人物设计）、`1fcb4332`（持久控制及可重试初始化）、`deecebb3`（有界只读 API 和默认拒绝写入）。隔离工作树保留，尚未合并主线。

## 已实现

- 人类/母体身份分离的可信宿主接口；短期凭据绑定工作区、命令哈希和授权来源，落盘锁内再查撤销与过期。不接受请求体中的 author/approvedBy。
- 不预填真实人物的设计结构：目标、课程、观察/恢复方法，以及外貌、服装、声音描述和可选版本化资产。修订保留作者与父版本，不扩大既有权限。
- 政策、设计历史、个体登记、初始化意图和幂等回执共用控制版本。暂停、恢复、归档、采用及受限回退均留历史。
- 控制先提交、独立个体文件后初始化；中途失败返回错误，同一请求重试修复相同 UUID，不重复创建或重复记账。
- 只读概览、列表、个体详情和审计；分页上限 50，游标绑定工作区/版本/集合，版本变更要求重新分页。状态损坏或观察到文件删除后拒绝返回旧成功。
- 服务源代码注册 `/api/cultivation`。生产构造没有安装可信写身份适配器，写入口返回 `cultivation_identity_unavailable`，不会靠 bearer 或本机 Origin 放行。

所有个体的 `dispatchAllowed` 仍为 false；就绪不等于运行。暂停/归档的取消结果为 `pending_confirmation`，不声称真实任务已停止。用量为 null、观察为 `not_observed`，不伪造为零成本或健康。

## 本轮发现及修复

1. 锁内再次验证时曾重新生成个体 UUID，导致资产检查针对另一身份；改为同一命令复用一次生成的 UUID，失败测试已转绿。
2. HTTP 写入曾把空数组参数展开成合法的暂停参数；现在在注入路由目标前要求对象，覆盖数组/null/字符串/布尔/数字五种拒绝情况。
3. 业务记录曾只验证字段结构，没有完整交叉核验归属、设计链和回执来源；增加九种损坏变体测试，并校验父子设计作者、权限收缩、导师归属、历史链、取消状态、审计动作及创建回执。
4. 增强校验时出现初始空记录与规范化业务默认值混用，联合测试立即捕获；保留原始基线记录再推进版本，回归已通过。

这些校验不证明能够抵抗本机管理员协调改写整套文件，也不是加密签名审计。文件缓存指纹仅用于普通文件变更失效，不宣称密码学完整性。
