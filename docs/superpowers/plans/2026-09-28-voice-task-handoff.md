# 元枢主聊天实时语音任务交接

日期：2026-09-28

## 范围

本记录是同日「手机实时通话试听版」的任务扩展，不替换原试听版部署记录。闭环为：通话提出任务 → 当前页面明确确认 → 现有文字执行器执行 → 结果持久回到发起通话的原聊天。

不新增公网入口，不改共享隧道和独立实验室，不接入 C 盘 OpenClaw，不改变文字主模型。不自动发起真实供应商付费通话。

## 使用与边界

- 开始通话前明确同意。可通过「交给元枢」修改转写后生成任务，或由语音提出任务提案；必须点击「确认执行」才受理。
- 最多一次提出 8 个任务，可依赖同批前项；提案确认有效期 90 秒，同时至多 4 个待确认提案。
- 挂断关闭未确认提案，不取消已受理任务。任务列表支持刷新和单独停止；提交结果不确定时查回执，不自动重新提交。
- 任务绑定发起聊天与幂等 requestId。真实切换聊天清理通话和输入状态；空聊天自身创建首个会话不卸载通话。
- 通话控制行固定，任务详情独立滚动，限制在当前可视高度内，避免挤出手机输入区。
- 默认全局独占、并发 1。任务使用服务端文字执行器与已有审批机制；这不是可靠的项目级工具沙箱，不能宣称项目权限隔离。

## 服务端实现

- `engine/voice-task-*`：原子任务日志、幂等接单、依赖调度、重启对账、证据核对、结果投递、鉴权 API。
- `engine/chat-voice-tools.mjs` 和 bridge/provider：受限 propose/list 工具；确认前不运行电脑工具，错误不切断正常音频。
- `engine/voice-run-admission.mjs`：与现有 run manager 共享全局占用边界；setup 失败也持久终态。
- `engine/session-origin-auth.mjs`、idle writer 与生命周期模块：会话存在/身份校验、忙时延迟回写、删除后不重建、压缩与写入互斥。
- 日志位于 `<RUNS_DIR>/voice-tasks/journal.json`。新建 worker session，不复制原聊天全部历史，不传播浏览器 Authorization 或 localhost 权限。
- 输出经 taskEvidence 核实产物摘要，以幂等 deliveryId 写入原聊天，再通过现有 `session_updated` SSE 通知刷新。
- POST/GET `/api/voice/tasks` 与 POST `/api/voice/tasks/:id/stop` 使用精确 Bearer 鉴权；变更请求强制允许来源，不接受 query token。
