# 元枢自主培养：第二阶段执行计划

日期：2026-09-30。承接已批准规格和第一阶段；在 `feat/agent-cultivation-ecology` 单写者实现，不改主工作区、不部署、不调用真实模型。

## 已查明的接入边界

`maintenance-approval.mjs` 只检查本机地址及请求头，不证明人工身份。`session-origin-auth.mjs` 能校验会话文件来源，但单凭调用者给出的 session ID 不能证明提交来自正在执行的母体。现有共享 bearer 仅用于读取认证，不能直接授予培养控制权。

因此本阶段交付真实存储上的业务内核和默认关闭的写入口。身份由宿主可信适配器注入；不存在适配器时明确返回 `cultivation_identity_unavailable`，不得用请求体、Origin、本机地址或环境变量里的布尔开关冒充人工确认。实际人工凭据签发及母体工具运行绑定尚待接入，不能宣称已完成真实用户闭环。

## 关键实现约束

- 所有 source actor 来自可信解析器且在锁内重验；JSON 命令先验证再复制，不能执行 getter。
- policy 更新与业务写入均共用 `control` 版本检查；幂等回执保存 actor 与命令哈希，重复请求不会多记审计。记录达到已有容量上限时拒绝，不自动删历史。
- 只创建服务端 UUID；同名人物不共用目录。个体初始状态用 intent ID 幂等恢复，不宣称两个文件原子提交。
- 修订与回退不增加权限；恢复/采用重新验证当前策略及资产。暂停、归档不依赖有效的执行授权，以免失效策略阻止用户停用。
- 核心先使用合成可信身份解析器测试，测试仅说明契约正确，不证明线上已有人类认证。
- 不导入 mother gene/emotion 初始化、模型执行器或计时器；真实人物设计留空，由小语以后实际提交。
