# 工作台与知识库入账链路审查

检查时间：2026-09-25（UTC；本机 UTC+8 已为9月26日）。范围：只读检查当前在线接口、源代码及工作空间记录。未触发付费分析、重新验收、自动审批或自主探索。

## 已确认事实

1. **经验数据存在，但经验沉淀台没有展示。** `/api/refine/status` 返回 experience.exists=true、49个二/三级标题、updatedAt=`2026-09-25T17:37:16.358Z`。49是标题数，不能当作49条已验证知识。`frontend/src/pages/Apps.tsx` 的 RefineView 请求了 status，但渲染只使用提案列表；提案为待审1、已采纳17、已拒绝3。该面板不是完整经验库浏览器。
2. **活动流不是持久账本。** `engine/unified-chat.mjs` 的 agentEventRing 只在内存保存最近200条，GET返回80条，页面展示40条；重启后清空。检查时GET返回0条。全局 `event-broadcast.ts` 从 pi SDK 扩展向此接口上报；元枢内部执行另有 run-event-log/work-explanation 链路，不能由此活动环为空推断普通会话未执行。终端 notify.py 也能向这个环上报，但本次没有调用。
3. **后台采集近期确实发生过，但没有合格学习标签。** 在线 `/api/dream/status` 显示20条观察、0条合格样本、phase=collecting。对loadEpisodes返回的逻辑去重记录按UTC日期聚合：9/16=1、9/19=3、9/20=4、9/21=4、9/22=1、9/24=2、9/25=5。不能据此证明这些日期用户没有使用Codex，只能证明采集并非仅有检查当天的记录。
4. **周期回放不等于主动获取新知识。** server在启动2分钟后及每6小时运行已有会话的增量采集与回放。游标为 `2026-09-25T17:48:16.711Z`。`evolution-cycle.mjs` 只有result.ok才写做梦日志，日志旧不能单独证明定时器停了。技能样本需要真实任务验收及独立/人工技能有效标签；0合格时不应自动晋升策略。
5. **自动技能沉淀触发范围有限。** 仓库内自动 nudgeSkill 挂在 time-engine 的 onTaskDone；未发现普通对话结束统一挂钩。refine分析有显式POST入口和前端按钮，不能认为每次正常聊天都会生成提案。未对所有外部脚本/计划任务做完整审计，因此不声称机器上完全没有其他调用来源。

## 额外代码风险（未证明已造成线上丢失）

`runDreamCycle` 单文件采集异常被吞掉，但批次游标仍推进至最大mtime；若确实发生读写失败，可能越过失败文件。当前没有足够错误记录确认曾发生。应增加每周期状态、失败计数及安全重试，不把这个风险写成已证实事故。

## 建议下一批小步修正

1. 知识库显示现有经验标题、更新时间及来源，并明确区分观察、待验证、已验证与已采用；不把条目数当作能力提升。
2. 工作台基于已有持久执行记录汇总日常活动，覆盖元枢/pi/定时任务；保留旧外部事件兼容，避免双计数。
3. 每轮采集持久记录成功/失败/跳过原因及上次时间；失败文件可重试，不被总游标越过。
4. 普通任务完成后先生成本地、去重的沉淀候选队列；模型提炼另设明确预算及触发条件，不能每轮无上限追加付费调用。采用仍经过原有验收和人工审批。

本批只合并已批准的证据闸门升级并完成诊断。上述新行为尚未实施，不宣称后台已具备持续无人值守自进化。
