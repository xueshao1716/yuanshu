# 元枢独立语音通话界面与启动反馈设计

日期：2026-09-28（Asia/Shanghai）
状态：已完成实现、最终全量验证与前端发布；本机和公网入口均已核对新版资源，真实手机通话体验待实测。

## 1. 用户目标与参考边界

解决两个问题：开始通话时“申请麦克风”等待不明，以及通话、文字聊天、转写和任务堆叠导致界面杂乱。

采用独立通话界面，继续绑定发起通话的原聊天。参考用户提出的 GPT 语音交互方向：明确的通话状态、集中且稳定的核心操作、按需查看文字。不复制品牌、配色或未经核实的现行界面。

官方 Voice Mode FAQ 的本次直接读取返回 HTTP 403，未获得可核验正文；因此本设计不声称复刻 ChatGPT 当前版本，也不引用未经核实的现行功能。参考入口为 `https://help.openai.com/en/articles/8400625-voice-mode-faq`。

继续使用 React、现有主题变量和图标。保留语音提出任务、页面明确确认、现有执行器执行、结果持久回原聊天的闭环。

## 2. 已有证据与尚未确认项

- `frontend/src/realtime/audio.mjs` 在 `await context.resume()` 之后才调用 `getUserMedia`。上一轮受控实验确认：resume 未完成时，麦克风请求次数为 0；释放后才出现请求。
- `frontend/src/realtime/call.mjs` 把音频初始化、创建会话、票据、WebSocket 和供应商就绪全部归为 `connecting`。受控实验确认所有阶段对外报告相同 phase。
- `RealtimeCall.tsx` 对这些阶段统一显示“正在申请麦克风并连接…”，不能帮助用户识别真正卡住的位置。
- 普通语音输入走 `voice-recorder.mjs`，直接申请麦克风，没有相同的 resume 前置等待。不把实时通话的问题泛化成所有录音入口的问题。
- 真实手机的分段耗时尚未采集。上述证据证明启动顺序和反馈存在问题，不证明用户这一次等待全部由其中某一步造成。

## 3. 方案选择

1. **采用：独立通话视图，保留原聊天归属。** 解决视觉堆叠，不引入新的会话存储模型；沿用已有任务结果投递。
2. 不采用本轮方案：独立语音会话记录。它能提供单独的通话历史，但涉及持久化、权限和上下文策略，超出本次界面与启动优化范围。
3. 不采用本轮方案：继续缩小当前内嵌面板。改动较少，但通话和文字输入仍争抢同一块高度，不符合用户要求。

## 4. 页面与交互

### 4.1 聊天入口与准备页

- 聊天保留一个清晰的“语音通话”入口；普通“语音输入”保持原有用途，两者不混用。
- 打开入口只进入独立准备页，不立即申请权限，不创建供应商连接，不预先计费。
- 准备页用短说明展示声音、有限当前聊天上下文的发送对象及计费，保留明确同意与“开始通话”。详细说明可展开；未同意时不能开始。
- 进入独立视图后，原聊天消息和输入框不同时可见，也不能被键盘或读屏误操作。隐藏聊天时保留其草稿和滚动位置，不以卸载输入组件实现切换。

### 4.2 通话主视图

- 顶部：小语、当前通话状态，以及明确的退出入口。
- 中央：立体流动光球作为动态主画面，按连接、聆听、回复与静音状态变化，辅以短状态文字；使用元枢既有主题，不新增沉重动画或图形依赖。
- 状态必须来源于真实连接或音频事件；尚未连通不能显示“正在聆听”，静音后不能继续暗示正在采音。不使用伪造音量驱动的动画。
- 通话时长从实际 `ready` 开始计算，不把授权等待算入通话时长。
- 底部操作区始终可见：静音／取消静音、打断回复、挂断；连接过程中提供取消，未就绪的操作不可用。
- 提供“通话／转写／任务”三个轻量视图切换；默认显示通话。切换只改变中部内容，不重建音频连接。
- 任务有待确认内容时显示数量和简短提示，不自动跳页，不弹出覆盖通话的任务面板。
- 转写和任务各自只保留一个主要纵向滚动区域，避免面板里再套小滚动窗。长文字换行；任务输入弹出键盘时操作仍可达。
- 长说明留在准备页与说明入口，通话中不常驻展示整段协议。

### 4.3 挂断、返回和生命周期

- 挂断后停在结束状态，用户仍能查看本次临时转写和任务，再点击“返回聊天”。再次通话需明确点击开始。
- 活跃或连接中离开通话的按钮直接标为“结束并返回聊天”；不设计含糊的返回按钮，也不把通话悄悄保留到后台。
- 本轮不做悬浮小窗、最小化持续通话、锁屏持续收音或自动重连。
- 切换真正不同的聊天、离开所属页面、退出登录或页面进入后台，继续释放通话资源。自身首次创建会话不视为切换，不卸载正在启动的通话。
- 未确认提案随通话结束而失效；已受理任务继续执行，完成后结果仍持久投递原聊天。
- 转写保留现有临时策略：同次页面生命周期内可查看；刷新、切换聊天后清空。不宣称已像任务结果一样保存进聊天。

### 4.4 移动端与桌面端

- 手机：通话视图占用应用可用内容区；暂时隐藏非通话底部导航，保留系统安全区。退出后恢复原导航。
- 桌面：在主内容区显示专用通话视图，暂时收起会挤压它的工具右栏；保留应用导航的明确退出能力，不另开浏览器窗口。
- 暂时隐藏周边界面不改写用户已有侧栏设置；退出时恢复。陪伴公仔及其恢复按钮也仅在通话视图中临时隐藏，避免遮挡操作。不能通过全局覆盖层来冒充独立页面。
- 采用现有动态视口高度与安全区处理。验证 390×844、390×460 和桌面宽屏；键盘、横屏和字体放大时按钮不被截断。
- 键盘焦点进入通话标题或首个可用操作，退出返回原入口；隐藏内容不可聚焦。支持减少动态效果偏好。

## 5. 启动顺序与错误反馈

### 5.1 发起动作

- 用户同意并点击开始后，在同一点击处理过程中立即发起 `getUserMedia` 与音频引擎 resume；不在请求麦克风之前等待 resume、会话创建或网络请求。
- 二者可并发准备，但未完成授权、音频初始化及服务端 ready 前，音轨保持禁用，不向供应商发送麦克风音频。
- 麦克风返回的流由启动流程立即接管；即使其他初始化仍未完成，也能在取消、失败或超时后释放。晚到的授权结果必须立即停止音轨。
- 保留 generation／abort 防护：挂断后任何迟到的 Promise 或回调都不能重开通话。并行准备的失败要及时捕获，不产生未处理拒绝。
- 不以取消登录校验、预连接付费供应商或放宽来源校验换取表面速度。

### 5.2 状态与耗时

保留现有 idle／connecting／ready 生命周期语义，增加细分启动阶段，避免影响音频互斥和任务发送条件：

1. 等待麦克风授权：提示查看浏览器或系统弹窗，并可取消。
2. 准备音频：权限已获得，但引擎或采音模块尚未就绪。
3. 准备聊天：仅在确需创建或确认会话时显示。
4. 验证连接：申请本次连接票据。
5. 连接语音服务：建立 WebSocket，等待语音服务 ready。
6. 已连接：可以说话，显示实际静音状态。

如多个本地准备动作同时进行，优先呈现尚未完成的授权；授权完成后再显示剩余准备步骤。授权完成后不得继续写“正在申请麦克风”。

记录从点击开始到各边界的相对耗时（毫秒），用于诊断，不包含音频、转写、聊天正文、票据、密钥或完整请求地址。本轮默认仅本次本地诊断，不新增远程遥测上传。

服务端当前不发“鉴权成功／供应商开始握手”的中间事件；前端不伪造这两个步骤的精确分界。先记录浏览器可直接观察的边界，必要时另行设计不含敏感信息的服务端阶段事件。

保留现有总启动超时上限，显示超时发生的实际阶段及重试操作，不把所有失败都解释成网络问题；明确区分权限拒绝、设备不可用、音频初始化失败和服务连接失败。

实现以 `failureStage` 在资源清理前保留失败阶段，新通话开始时清空。麦克风、音频、会话、凭证、连接及服务就绪超时分别解释；设备缺失／占用、音频引擎与处理模块失败有独立恢复建议，未知错误保持中性，不统一归因网络。

## 6. 组件与数据边界

- 将通话状态和生命周期从 `SendBox` 内移到当前聊天的稳定宿主；该宿主管理同一个通话实例、同意状态、转写、任务状态及视图选择。
- `SendBox` 只提供入口和与现有录音互斥的接线，不再容纳整个通话面板。
- `ChatArea` 负责聊天／通话内容视图切换；`AppLayout` 只接收专注通话的展示状态，以暂时收起导航或右栏，不接管音频逻辑。
- 保留 `createSessionViewOwner` 的首次会话接管规则。准备页打开、开始、创建首个 session、切换通话子视图均不得意外卸载音频宿主。
- 采音模块只负责权限、音频准备与清理；连接模块只负责阶段、票据和传输；展示组件只根据状态渲染。接线按职责拆分，避免扩大现有大组件。
- 不改变任务确认协议、requestId 幂等、权限检查、持久回写和现有原聊天 SSE 刷新路径。

## 7. 实施后的验收要求

- 先写失败测试，证明 resume 长时间未完成时麦克风申请仍立即发起；拒绝、取消、超时以及迟到授权均无音轨、播放器和连接泄漏。
- 阶段测试逐个控制授权、音频、session、ticket、socket、ready：提示与阶段一致；录音发送仍受 ready 门控；双击不重复创建连接。
- 布局和交互测试覆盖独立显示、原聊天隐藏且不可聚焦、返回恢复草稿、按钮可达、转写／任务切换不重连、首次创建会话不掉线。
- 保留任务回归：未确认不执行；确认后挂断不取消；结果回原聊天；刷新不重复受理；失败状态可理解。
- 使用隔离工作空间执行全量验证、类型检查、非线上构建和前端检查；不直接运行会改真实工作空间的测试。
- 浏览器验收使用模拟供应商和临时数据，不自动触发付费模型。真实手机授权速度、音质及公网实际连接单独记录，不用模拟测试冒充真人验收。
- UI 检查需实际可用的截图或页面检查证据；无法查看图像时明确说明，不宣称完成目视验收。

## 8. 本轮不做与发布边界

不做视频、屏幕共享、相机入口、新的供应商或模型切换；不持久保存通话音频或新增语音历史；不改共享隧道、独立实验室或 C 盘 OpenClaw。

详细设计审阅通过后再实施。保护已有脏改动，不整树覆盖，不自动提交或推送。正式构建前先通过隔离验证；只改前端不重启服务，保留旧指纹资源。若后来确需改服务端，须重新核实活动任务、主进程及看门狗，另行明确受控发布步骤。

## 9. 设计自检

- 独立的是界面，不是另一套会话和任务归属。
- 进入页面、同意授权、开始采音、允许发包和确认任务分别有明确边界。
- 不把未经测量的真实手机延迟归为已确认根因，不承诺“秒连”。
- 显示临时转写与任务结果持久化的区别；返回行为和后台行为无隐藏继续收音。
- 本设计只解决启动反馈和通话界面，不扩大到历史存储或通话平台重构。
