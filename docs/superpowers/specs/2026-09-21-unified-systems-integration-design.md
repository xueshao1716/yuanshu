## 目标与范围

在元枢提供统一任务入口，使会话、天团和 AIBody 能调用同一组外部系统适配器，并追踪真实执行者、会话、过程、结果和治理边界。

用户明确：OpenClaw 只使用 D:/linxinyu-system 下的实例，排除 C 盘 OpenClaw。接入范围还包括 Hermes、D:/xi-system，以及 D:/linxinyu-system 的母体和人格资产层。

## 方案比较

1. 推荐：元枢统一任务协议，各系统独立适配。统一用户入口，同时保留原生工具、记忆、执行与治理。
2. 全部包装成模型聊天接口：实现快，但容易丢失工具过程、停止、审批和真正执行者，不适合本需求。
3. 合并代码与记忆数据库：改动大，生命周期和人格冲突风险高，不作为本轮方案。

## 接口与运行流程

新增系统注册与能力查询接口，提供 installed、reachable、authenticated、ready 分开的状态；目录存在仅代表 installed。

现有任务创建入口接受显式 targetSystemId。默认本地 pi/元枢路径保持兼容；外部任务按适配器分派。第一版由用户或天团计划显式选执行系统。

适配器统一提供 inspect、submit、readRun、subscribe、cancel；每项带能力声明。母体提供状态、谱系、提案等独立读取能力，不伪装成文本模型。

流程：验证目标和权限 → 创建元枢任务 → 提交外部系统 → 持久化外部运行/会话映射 → 归一化过程事件 → 收取结果与交付物 → 确认终态。

运行记录分开保存执行系统及引擎、文本模型、媒体模型。字段没有来源证据时标记未知，不从设置页默认值推断。

每条外部事件保留来源、原始事件编号和元枢序号，去重后支持断线回放。禁止以读取历史快照冒充正在运行。

会话映射保存元枢会话与外部会话的对应关系。外部上下文由该系统自己维护，跨系统上下文使用明确的任务摘要和附件引用。

## 失败、停止与治理

提交有幂等键和来源记录；提交后超时标记待核对，先查询已有外部运行，不自动重投到另一个系统。

停止先进入停止请求状态，收到目标确认后才能标记已停止。仅断开本地 SSE 不能作为外部任务停止证据。原生工具无法立即中断时如实显示其状态。

重启恢复先对账外部运行，无法查询时标记结果未知。目标服务离线显示离线，不展示为已接通。

认证只在服务端读取本地配置，前端、运行日志、版本库不得携带密钥。文件交付只接受允许目录中的可验证产物，防止越界路径和符号链接逃逸。

任务接入不自动批准母体进化提案、不改写各系统人格、不自动向微信或 Matrix 发送消息。母体读取避免触发自动晋升和持久化写回。

## 实施顺序与交付

1. 统一系统注册、能力检查、任务映射和事件协议；用隔离数据验证重复提交、断流、停止、重启对账。
2. 接通 D 盘 OpenClaw 与 Hermes 原生任务；确认实际版本、健康与认证。
3. 接入 Linxinyu 母体状态和治理观察；将人格、母体、宿主显示为关联关系。
4. 为曦补原生任务桥，接入 Rust 工具执行、状态和取消；修改前备份，保持原有通道独立运行。
5. 元枢工作台增加系统选择、能力状态和来源显示；天团与 AIBody 使用相同适配器。
6. 真实任务验收后更新版本号和交付说明，客户端按最终功能重新构建。

## 完成标准

- OpenClaw、Hermes、曦分别完成两轮连续对话和一次含工具的任务，有真实外部运行证据。
- 完成一次生图后继续工具任务，能够追溯文本模型、媒体模型、执行系统和真实图片文件；不支持媒体的系统明确声明能力限制。
- 覆盖刷新页面、SSE 断开重连、主动停止、目标离线、提交超时、服务重启和同会话重复提交。

- 母体状态读取得到来源与时间，观测不自动审批、不触发进化写回。
- 核心测试使用隔离工作区；完成类型检查、前端构建、适用的界面检查和真实页面验证。
