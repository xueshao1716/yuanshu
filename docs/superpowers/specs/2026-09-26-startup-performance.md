# 系统2 · 第2项：启动提速

范围：首屏启动和上次会话恢复。保留现有主题、字体、鉴权、会话刷新、草稿和模型行为；不承诺模型推理提速。

1. 用隔离构建与合成会话建立基线；外部字体人为延迟，对比首屏可输入时间；统计启动会话目录请求次数。
2. 若确认阻塞，将装饰字体移出首屏关键路径，加载成功后仍使用原字体。
3. 将会话恢复与 SWR 的同一份目录结果合并；每次登录只恢复一次，用户主动选择优先，失败后可重试。
4. 真实 Chrome 桌面/手机视口验证；确定性请求计数与恢复行为作回归门槛，时间作观测数据，不以噪声设硬阈值。
5. 隔离全量测试、类型检查、构建、设计检测，审查差异后合入。只构建线上前端，不重启后端，不打原生包。

不改第3–7项，不安装文章中的外部技能，不用真实会话做测试。

## 测量与验收记录

2026-09-26，Chrome 桌面浏览器，两种视口，各组交替前后执行 3 次，共 24 个样本。接口全部用合成数据，字体请求分别施加 0 / 2000ms 延迟。计时终点为输入框可见且成功写入草稿，而非页面 load 事件。下表为加入正式服务脚本 CSP 限制并修正字体激活方式后的最终对照。

| 视口 | 字体延迟 | 改前中位数 | 改后中位数 |
| --- | --- | --- | --- |
| 1440px | 0ms | 513ms | 425ms |
| 1440px | 2000ms | 2534ms | 399ms |
| 390px | 0ms | 445ms | 382ms |
| 390px | 2000ms | 2492ms | 381ms |

启动会话目录请求从每次 2 次减为 1 次。慢字体不再阻挡输入；字体到达后依旧应用，已输入的草稿保留。早期一轮无延迟的窄视口样本反而略慢（293→336ms），可见小样本有噪声，不能宣称所有环境均提速，更不能据此宣称模型输出或全系统提速。这里的手机是桌面 Chrome 的窄视口，不是实体手机。

顺带发现 SWR 重试回调误将错误对象当作函数，已改为调用实际重验函数，401 不重试、最多重试三次。退出清除内存令牌，防止迟到重试继续携带旧凭证。

补测发现：退出时清空数据但保留请求去重标记，立即登录会复用已失效的旧请求而无法恢复会话。登录前需要使旧请求标记失效，再启用已验证的新凭证。

原始测量保存在隔离工作树 `tmp/startup-comparison.json`；回归脚本为 `tests/e2e/startup-performance.playwright.mjs` 与 `tests/e2e/startup-session-regression.playwright.mjs`。所有浏览器回归均禁止访问真实 API、WebSocket 与外部媒体。

设计检测：store.tsx 检测无发现；HTML 检测因本机缺少解析模块而退回正则扫描，不能据此宣称完整视觉检查通过。此次未更改色彩/布局，字体加载顺序改变可能先显示系统后备字体。

正式服务校验发现 CSP 为 `script-src 'self'`，会拦截 HTML 的内联 onload。已改由外部主模块注册事件，兼容加载已完成和尚未完成两种时序，没有放开内联脚本。浏览器回归服务器已启用同样的脚本限制。最终 7 项会话回归通过：恢复、新建优先、503后重试、会话不存在、退出后迟到响应、立即重新登录、字体加载失败；24 项加载对照通过，无页面脚本异常。

最终隔离工作树 `npm run verify` 退出码 0：2205/2205 单元测试、类型检查、构建全部通过。早期边测边补充代码的运行因源码指纹变化而失效，不作为最终通过依据。现有大 chunk 与 Toast 混合导入构建警告仍在，未通过扩大范围掩盖。
