# 元枢：自主智能体培养与双向学习生态

日期：2026-09-30。状态：方向已获用户同意；本书面规格待审阅，尚未实施。

## 1. 目标与定义

允许小语在用户授予的范围内设计、培养自己的持久智能体；用户通过一个面板观察并干预。培养不仅服务于任务产出，也应支持 aibody 土壤良性、可进化性，以及有语境的情感表达多样性。来自培养过程的经验可以反哺小语，但不能形成自我证明的循环。

本规格由工程侧定义基础设施与边界，不冒充小语自己的生态设计。具体人物、培养理念、情绪表达方案和实验由小语实际提交，保留作者、运行来源与版本。

“培养/进化”指档案、记忆、知识、方法、培养计划及有证据的配置演进；不等于模型权重训练、意识证明，也不能用交互次数代表真实成长。“情绪”是系统状态与表达设计，不证明主观感受。

成功条件：她可以提出不同的培养路线、在授权内行动、从可追溯的成败中学习；用户看得见实际发生了什么，并能停止、纠正和回退支持版本化的配置。

## 2. 方案取舍与首期范围

- 选用“持久档案 + 有界任务 + 证据回流”：复用现有天团任务能力与知识治理，增加独立培养身份和观察入口。
- 不选“仅增加天团角色卡”：无法表达长期记忆、培养设计版本和双向学习。
- 不选“每个孩子运行完整母体副本”：当前共享状态与权限继承会增加污染、费用及失控风险。

首期闭环：小语提交设计 → 策略校验 → 建立独立档案 → 执行一次有界培养任务 → 提交经验候选 → 验证或试验 → 采纳、修订或舍弃 → 面板可观察与干预。

不包含模型训练、自繁殖、多代谱系、任意代码执行、新的社交平台、全量 aibody 重写、自动发版或自动修改审批规则。外貌、服装和声音复用已有角色设计与资产绑定，媒体生成仍走现有授权能力。

## 3. 设计权、行动权与干预权

小语自主设计以下内容，系统不以预填人设代替她的决定：

- 为什么培养、培养谁，以及不同个体的兴趣、表达特点与边界。
- 外貌、服装、声音及其设计理由；只引用有权使用的资产。
- 目标、课程、互动形式、反思方式、试验与评估标准。
- 如何观察土壤健康、如何处理持续极端状态、如何根据证据调整。

工程提供版本化结构、受限执行接口、证据与审计；用户提供或修改授权策略。在有效策略内，符合边界的设计、任务和可逆调整不逐项请批。策略缺失、超限或触及保护项时停止对应操作并显示原因，不靠提示词自行放行。

首期可配置默认值：最多 3 个培养对象；最多 1 个培养任务并发；付费预算为 0；远程模型调用关闭；禁止再养下一代。用户可以另行授权资源上限与远程调用，已批准设计方向不等于批准消耗或启动任务。

授权至少覆盖模型、工具、数据范围、有效期/调度窗口、请求上限和费用上限。未指定权限不继承；不复制母体的整库私人记忆、凭据或 computer-use 权限。密钥由现有服务代理使用，不进入孩子上下文。

母体核心身份、人格/基因 baseline、权限扩张、审批策略修改仍走现有人类批准机制。模型互评、导师接受、子智能体同意均不能冒充用户批准。

用户可以查看、暂停、取消、显式恢复、修正、归档及回退已版本化配置。任何智能体不能取消用户访问权、删除审计或批准自己的保护项提案。回退配置不抹除历史，也不能撤销已经发生的外部副作用。

## 4. 三层状态与情感多样性

| 层 | 内容 | 变更路径 |
| --- | --- | --- |
| 稳定倾向 | 长期人格、价值边界、基因基线 | 证据提案；保护项交用户批准 |
| 临时情绪/表达 | 当下语境、短期情绪状态、表达方式 | 范围内试验；不直接固化为基线 |
| 知识/方法 | 可验证知识、技能方法、反例 | 候选、验证、试验、采纳与退役 |

情感多样性不是快乐最大化、服从最大化、随机情绪切换，也不以诱导痛苦、依赖或冲突作为成长捷径。允许有语境的认真、幽默、不同意及低落表达；具体表达与恢复方案由小语设计。

系统提供证据来源、重复自引用、持续极端状态与恢复、漂移、实际效果和回归风险等观察维度；小语可以提出新的观察方法。缺数据标为“未观察”，不能显示为健康。首期不提供没有验证依据的综合健康分、经验值或成长百分比。

## 5. 模块边界与既有系统接入

| 模块 | 单一职责 | 接入原则 |
| --- | --- | --- |
| 策略与培养仓库 | 授权、设计版本、身份与生命周期 | 持久化、服务端校验，不依赖模型自律 |
| 培养调度适配器 | 生成有界任务、追踪、取消与恢复 | 复用任务生命周期及低优先级调度约束 |
| 经验桥 | 源事件转为可追溯知识/试验候选 | 复用知识队列，不建立旁路真理库 |
| aibody 观察投影 | 展示母体及培养对象的不同状态 | 引用同一记录，不执行任务或代批进化 |
| 培养观察面板 | 查看实际设计、运行、经验与控制 | 单一主入口，其他页面只摘要或跳转 |

现有 `aibody-runtime` 的 mother/sovereign/analyst/companion 是运行投影，不当作已经存在的持久培养对象；现有任务子智能体也不因改名就具有长期身份。

已核查 `engine/gene.mjs` 存在模块级工作区、genome、observations 等共享状态，`engine/emotion.mjs` 也使用共享初始化。禁止在同一服务中对每个孩子重复调用母体初始化函数切换目录。

孩子使用按作用域创建的存储实例、纯状态归约器或独立适配器；母体引擎保持原工作区与运行状态。可复用 `createGeneStore` 等可实例化原语，但不能仅凭工厂存在就认定整条链路已隔离。身份、情绪、记忆、提案、外貌和声音均须验证无交叉写入。

天团负责有界执行与审阅证据，不授予孩子递归调度或任意工具能力；不把模型 REVIEW 当作人工验收。现有子任务契约没有的文件、网络、媒体等权限，必须由授权适配器明确提供，否则返回不支持。

知识系统继续拥有采集、验证与提交状态；运行任务继续拥有执行事实。培养面板只保存或投影权威记录 ID，不复制一套互相矛盾的状态。

## 6. 最小数据契约

以下是拟新增契约，不表示当前已有实现。所有记录包含工作区作用域、服务生成的 ID、版本及创建/修改时间；服务从认证身份/运行上下文确定作者，不能信任模型传入的 `author` 或 `approvedBy`。

| 记录 | 必需内容 |
| --- | --- |
| CultivationPolicy | 用户授权来源、有效期、模型/工具/数据白名单、人口/并发/请求/费用上限、策略版本 |
| DesignRevision | 小语实际提交的设计、目标与差异、理由、评估/恢复方法、父版本、来源 run ID、校验结论 |
| CultivatedAgent | 导师及 agent ID、采用的设计版本、独立状态作用域、生命周期、受限数据引用、外貌/声音绑定 |
| CultivationRun | 目标、对象、设计/策略版本、幂等键、宿主任务 ID、租约、状态、输出/错误、用量与证据引用 |
| ExperienceCandidate | 源事件/来源角色、派生祖先、内容范围、哈希、论点与反例、验证/试验/采纳状态、知识记录引用 |
| Trial/Adoption | 预先定义的效果判据、试验范围与期限、实际结果、评审身份、采纳/修订/舍弃理由、配置版本引用 |

事件来源区分用户直接反馈、工具/测试结果、模型推断与智能体间生成内容。哈希仅用于内容一致性，不证明结论为真；没有外部证据的经验允许保留为假设，不伪装成事实。

运行数据保存在业务工作区的 `工程/智能体培养/`；子状态按服务端生成的 agent ID 分区，禁止按显示名称或数组序号寻址。知识正文沿用现有 `记忆/知识/` 及其权限约束，只在培养记录里保留引用。

写入须有版本检查与原子持久化；跨任务、知识、培养记录用幂等 ID、待同步事件和可重试对账保持一致，不假设跨文件事务天然存在。删除引用或证据不可读时标记失效，不自行补造证据。

## 7. 生命周期与失败处理

- 设计：草稿 → 校验 → 在授权内采用；不通过保留原因与草稿。保护项分流到既有待批准提案，不以采用设计绕过批准。
- 个体：待设计 → 就绪 → 暂停/归档；归档禁止新任务并保留可见历史。恢复必须重新检查当前策略。
- 任务：排队 → 运行 → 成功/失败/取消；外部结果无法确定时进入“结果待核对”，不得自动重放有副作用的调用。
- 经验：候选 → 验证 → 有界试验 → 采纳/修订/舍弃；纯事实验证不需要伪造一次试验，状态应注明适用路径。

持久个体不是常驻后台进程。任务有超时、取消信号、输出限制、资源预留和追踪记录；暂停阻止新派发并请求取消当前任务，未确认结束前不得显示“已停止”。

刷新或重启不重复生成个体、不重复执行任务、不清空预算，也不自动解除暂停。失效租约先核对宿主任务；确定未执行才允许重排。工作区/策略/设计版本变更后重新校验，不能沿用过期授权。

正常回流不会自动引发下一轮无限学习。任务只有明确计划或外部事件才入队；中间摘要、模型自评及知识自产事件不得再次作为原始事件自动入队。

## 8. 双向学习与防止自我证明

闭环为：共享经历 → 经验候选 → 来源核验 → 有界验证/试验 → 采纳、修订或舍弃。导师和孩子都可以提交候选，双方是否采用是分别记录的决定。

每个候选保留完整派生关系；母体观点被孩子重复、多人复述同一内容，不增加独立证据数量。自评与真实任务结果分栏，用户是否接受单独存证。由模型概括的“用户满意”不是用户反馈。

跨个体共享必须符合授权数据范围，并检查派生内容是否泄露原始私密信息；模型声称已脱敏不作为自动放行依据。撤销范围后停止后续使用并使相关候选失效待核对，不能声称已经撤销外部模型收到的内容。

孩子对话、合成事件、模型评审不得冒充用户交互输入现有情绪标签或 gene observations。人格长期调整只形成符合现有证据标准的提案，不能改写证据门、自动批准或编造跨日事件。

失败和反例也可作为经验；失败原因未经验证时保持假设。候选不直接注入为已确立知识；试验内容在受限上下文中标注实验身份，可因反例退役。

## 9. 拟议服务接口与观察面板

统一命名空间 `/api/cultivation`，复用现有认证和权限体系；以下是接口职责，具体实现需逐项契约测试。

- 只读：`GET /overview`、`/agents`、`/agents/:id`、`/designs`、`/runs`、`/events`、`/experience`。列表有游标/上限与作用域过滤，查看不触发模型调用或采集。
- 设计提交：`POST /designs`、`/agents`、`/runs`、`/experience`；携带基于记录版本的幂等请求，由服务验证调用者、策略和数据来源。提交者不决定授权结果。
- 用户控制：`PUT /policy`、`POST /agents/:id/pause|resume|archive`、`POST /runs/:id/cancel`、`POST /agents/:id/rollback`。修正设计通过有作者记录的新版本提交，不覆盖旧版本。
- 保护项：引用现有审批接口与提案 ID，不新增直接修改 baseline 的捷径。不提供“执行模型返回代码/配置”的通用接口。

面板包含四块可切换内容：个体与小语设计、真实运行时间线、双向学习证据、授权与资源。概览先回答“她在养谁、正在做什么、学到什么、哪里需要你处理”，详情按需展开。

声音、立绘、外貌/服装属于各个人物，保留并按 ID 绑定。灵魂培养中心只展示生态摘要与入口；知识页面打开既有候选/知识记录；天团打开任务证据；aibody 展示同源状态，不重复建设管理页。

首次无真实设计时显示“等待小语提交设计”；无运行、无效果证据、用量未知均如实显示，不填充演示数据。区分实际/估算/未知用量和费用；未知不能记作 0。

## 10. 资源、隐私与可靠性约束

与知识自主化共用或受同一资源仲裁器约束：培养任务不能借第二条队列绕过并发、成本或聊天/语音优先级。启动延迟、后台恢复和压力指标沿用知识自主化设计；挂起时释放可释放资源，不能靠长期轮询占用前台。

预算使用持久日账、请求前预留与结束后结算；未配置授权或无法可靠预估上限的付费请求不启动。失败也计入已发生请求和已知费用；未知费用保留待核对额度，不释放为可重复消费。

前台忙时不发起新的培养模型调用；已在途任务只按实际支持能力取消，不声称网络请求一定可撤销。API 查询分页且禁止每次全量扫描；面板隐藏/卸载停止轮询、释放订阅。

所有工作区及 agent ID 服务端解析并校验边界；跨作用域读取、提示注入、越权工具参数和模型伪造审批均拒绝。输出作为数据展示，不注入可执行脚本或任意命令。

开源仓库只包含通用代码、合成测试夹具及经许可公开的资产；真实培养档案、私有记忆、域名、密钥、日志和运行产物不得提交。审计供授权用户查看，导出必须脱敏并保留来源类型。

## 11. 验收条件与交付边界

1. 无设计、无授权、无历史的初始页面准确显示空状态；查看各页面零模型调用。
2. 经授权的小语提交设计可产生有来源的版本和独立个体；伪造作者、批准身份、超限模型/工具/数据请求均被拒绝。
3. 修改孩子 A 的情绪、记忆、提案、服装、声音，不改变孩子 B 或母体；并发、重启后同样成立。测试覆盖现有引擎共享状态陷阱。
4. 一条真实有界任务从计划到结果再到经验候选可追踪；模型自评、用户验收、工具结果不混淆，重复派生证据不增权。
5. 经验采用与退役有验证结果、作用域和版本；母体 baseline 不自动变化，现有基因证据门与人类审批保持有效。
6. 暂停、取消、恢复、超时、陈旧版本、租约失效、未知外部结果和部分落盘失败可重现；重启不重复调用，不解除暂停，不清空预算。
7. 预算为 0/未授权时没有远程付费调用；未知用量不展示为 0，知识与培养不能分开绕过资源限制。
8. 路径穿越、跨工作区、跨个体越权、私密派生数据外泄和提示注入用合成夹具验证；真实业务数据不用作测试靶子。
9. 隐藏面板无后台轮询；沿用知识自主化压力验收：至少 100 次模拟前台调用，新增首响 p95 不高于 100ms；60 秒采样事件循环 p95 不高于 50ms，记录机器与负载条件。
10. 面板入口与知识、天团、aibody 的跳转可用；声音/立绘不串人；记录以同一 ID 对账，不能出现两个页面各自判定成功。

实现时先做隔离存储、授权与状态机测试，再连有界执行和经验桥，最后接面板。核心逻辑按仓库 TDD；完整验收使用隔离的 `npm run verify`，不得直接对真实业务工作区运行测试。真实模型验证必须使用另行授权的额度，并与模拟测试结果分开报告。

本次仅提交设计，不修改运行配置，不召唤小语执行设计任务，不启用后台培养、不升级版本、不重启、不打包。书面规格审阅通过后再形成实施计划；上线必须另行报告实际完成与尚未验证部分。
