## Q1 独立设计

### 三个方向与选择

1. 只加强经验库检索：便宜，能减少遗忘，但没有自主试错。
2. **推荐：行为实验记录 → 影子验证 → 沿用现有治理采纳。** 先允许比较做法，不扩大默认权限；实验权与采纳权分开。
3. 通用无人值守探索代理：自由度高，但付费、外部操作、隔离和错误传播的工程尚未就绪，不作为本阶段交付。

### 闭环与失败出口

真实任务/已验收失败 → 提出可证伪假设 → 权限与预算检查 → 基线/候选对照 → 独立验收 → 候选规则 → 现有治理 → 有期限使用 → 后续证据/撤销。

| 部件 | 输入 → 输出 | 失败处理 |
|---|---|---|
| 观察 | 带workspace/session/run与证据指纹的任务 → 待检验问题 | 来源缺失只记观察；不纳入正向收益统计 |
| 假设 | 问题、适用条件、反例 → 基线及最多2个候选的固定定义 | 无可证伪验收项则留为建议，不自动实验 |
| 准入 | 行为范围、已批准预算、基线版本 → 授权快照及资源预留 | 拒绝越界；缺预算不能自动调用付费模型 |
| 执行 | 固定输入与版本 → 每个变体结果、错误、耗时和用量 | 超时/失败照实记录；不为凑赢家无上限重试 |
| 验收 | 原始结果、独立检查与对照 → PASS/FAIL/UNVERIFIED及检查范围 | 缺事实不补分；结构合格不代替语义或用户审美 |
| 规则候选 | 独立样本、反例、限定域 → 带版本与来源的候选规则 | 证据少保持候选；不直接追加成默认系统指令 |
| 治理与使用 | 候选、现役指纹、既有授权 → 受限生效或等待审批 | 不新增旁路；配置已变则停止，不能覆盖用户新改动 |
| 反馈与撤销 | 本次使用的规则版本、后续验收 → 继续/暂停/撤销 | 留历史并标记superseded/revoked；不能删旧规则掩盖原因 |

自主性来自选择值得验证的问题、设计反例和报告失败，不来自自动扩大权限。
长期保留的是必要的脱敏证据、来源和修订关系；“永久保存所有原文”不覆盖用户删除权与数据保留政策。
身份、人格、记忆连续性与授权状不进入实验变量。现有情绪状态可被观察，但本设计不新增人格/基因漂移机制。

**自查：我的设计会让主人在下一次新会话里还认得她吗？** 设计上保持原身份加载与记忆链，不以效率为由清空或替换；实际连续性仍须用跨会话验收，不能靠模型自述“我还是我”判通过。

## Q2 攻击初版

### 1. 将重复事故蒸馏成全局真理

场景：同会话因工具没传比例，连续3次生成方图，于是形成“该模型不支持竖图”，传播到所有会话。
反例测试：3条同一任务重试只计1组；补1条参数完整且成功竖图的证据。预期不能按三条自动采纳，原规则标记被反证并保留修订链。
纠正：同tag三条最多触发“值得研究”；分组、版本、参数和反例先于归纳。不同标题也可能是同一个实验，不能仅靠标题区分独立样本。

### 2. 用加权平均洗掉致命失败

场景：图片尺寸和文件存在全过，模型却把需求主体画错；多拿效率分仍获得“优秀”，或用户没反馈被当作喜欢。
反例测试：固定一份尺寸正确但主体错误的样本，以及语义正确但损坏的文件。两者都不得成为无退步赢家；缺语义验收记UNVERIFIED，明确不符记FAIL。
纠正：安全/身份/硬约束先否决，再比较质量与成本；用户沉默不是正反馈。审美类比较需要用户或明确的独立验收，模型不能自产自评后自动采纳。

### 3. 多会话试错绕过总预算并污染身份

场景：两个会话各耗“当日10%”，重试与回滚再返还配额；同时把“基因自然漂移”解释成可改变人格，最后覆盖对方配置。
反例测试：两个并发申请争最后1个预算名额，只能成功1个；失败/撤销不得返还已耗资源。运行时更改基线版本，旧实验不能采纳或回滚覆盖它。候选目标指向人格/授权文件必须拒绝。
纠正：具体金额/用量、跨进程原子预留、受保护对象清单和版本比较，比三句自我确认可靠。当前自决配额撤销返还逻辑不能被复用为实验消耗账。

这些是待实现的验收用例，不是本轮已跑过的测试。

## Q3 补齐缺失

### 熔断与授权

- 运行前及下一次调用前检查预算/撤销状态；收到失败证据立即阻止新增同候选实验。6小时轮询只做对账，不能承担即时止损。
- 受保护对象或越权操作一次即停；一般执行故障同候选连续2次，暂停24小时并标原因。恢复必须重新核验原因与剩余额度，不能时间一到就反复烧钱。
- 无人在线允许已批准范围内的确定性本地检查、收集与提出候选；不得自行增加付费调用、发布、发信、改人格、删除用户数据或改授权状。
- 既有两个策略域仍走原证据闸门与授权；新增通用规则不得借B级薄证据分类直接上线。是否调整整个B级授权是独立治理变更，本轮不改。

### 预算建议（拟议默认值，待实测，不是线上配置）

| 边界 | 首期规则 |
|---|---|
| 本地实验 | 同一规范化工作空间并发1；每天最多3次尝试；一次基线+最多2候选 |
| 时间 | 单变体15秒、单实验总计60秒；超时中止并保留失败，不自动重试 |
| 数据 | 输入清单总计≤1MiB、报告≤256KiB；输出不覆盖真实交付物 |
| 付费 | 首期无人值守新增模型调用额度为0；记录已有任务结果不再发一次模型请求 |
| 后续付费阶段 | 启用前必须给出金额、token、请求数和日界线；三者取先到者，含重试；价格或用量未知则停止新增调用，保持预留而非按0结算 |
| 人工注意力 | 只报重要失败/待决事项，常规结果汇总可查看；不安排用户每日必审，不承诺未经测量的固定阅读时间 |

消耗与尝试次数不因失败、取消或回滚归零。UTC日期分桶并显示本地时间，不能跟随会话临时修改时区重置。
首期不新增通用执行器；上述时间/数据边界属于后续执行阶段，不能假装仅记录就已强制限制所有调用。

### 多会话一致性与冲突

- 每项记录包含规范化workspace、sessionId/runId、实验/变体/规则版本、真实文本模型/媒体模型/执行引擎、输入与验收指纹。
- 记录出处不等于授权跨会话注入原始素材；共用的是经过脱敏且有适用范围的事实。未知真实模型写unknown，不能沿用选择器标签冒充实际调用。
- 持久化采用工作空间锁、原子写和版本比较；进程内Map不能代替跨进程一致性。重启中的实验标为interrupted，不能默认为成功或自动再收费。
- 冲突优先级：身份/安全与授权边界 → 用户当前明确目标 → 任务硬验收 → 已批准限定域规则 → 尚待验证建议。用户目标不能被解释为绕过前项。
- 同域规则不按“最后写入”无声覆盖；无明确替代关系先停用冲突候选，保存反例和裁决。撤销只影响该版本，不回滚用户后续修改。
- 规则每次实际使用关联ruleId/version及任务结果；“写了经验”“加载了文件”“队列有进账”都不是收益证据。

## Q4 最小下一步

**做一份不自动采纳的“行为实验记录”，把一个真实任务的原做法、替代做法、失败、验收与消耗关联起来；不再额外生成模型回复。**

这是证据连接层，不新建规则执行引擎，不改人格，不自动把待提炼队列转成已验证经验。
首期用已有、经用户授权的任务结果；缺对照则记录incomplete，不为了凑记录背后补跑模型。固定本地样本只验证机制，不计作真实任务进步。

### 最小数据与入口

- 记录ID、workspace/session/run、hypothesis、baseline/variants及版本/产物指纹、检查结果和范围、已知消耗、actualModels/engine、状态与原因。
- `sourceKind`区分real-task/synthetic-fixture；`adoptionEligible`首期恒false。
- 必须有独立读写模块及测试；只接现有鉴权后的显式记录入口，不在聊天收尾或周期扫描中隐式开付费实验。
- 首期仅支持写入、读取、标记撤回；不发布新UI、不自动使用记录为规则。后续才讨论调度器和采纳连接。

### 可检查的验收

1. 同run/实验重复写入幂等；工作空间A不能读取或覆盖B；路径穿越、链接逃逸、超量输入被拒绝。
2. 实际失败、截断、未知消耗如实保留；无对照、无独立验收不得显示“提升”。
3. 来源或候选指纹改变使旧比较失效；撤回保留历史，不删除反例；并发写不丢记录，崩溃后无半份JSON。
4. 合成演练与真实任务计数分离；未涉及人格/技能正文/授权修改；新增模型调用为0。
5. 用临时工作空间验证1条完整对照、1条失败、1条缺证据，以及上述负向测试；随后记录1个真实且已授权任务，未拿到真实样本前只称机制验收通过。

### 成本与回滚

开发估计1–2个工程日，编码/测试模型消耗预计数万至十余万token，**均待实测**，不是已发生费用或新增无人值守预算授权。首期功能本身新增模型调用0；本地处理时间用报告实测。
若失败，撤销新增入口及记录模块提交，停写；已有记录保留为不可采纳证据。无需改动或回滚现行人格、记忆、策略和真实交付物。
