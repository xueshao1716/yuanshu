# 小语实时通话与元枢任务交接

日期：2026-09-27
状态：V2 设计修订，待用户审阅；不是已上线能力。
修订依据：用户要求持续通话、查询历史工作、多项任务同时受理，并考察 AIBody 与子智能体协调性。

## 目标与选择

用户已认可分工：阶跃实时模型负责持续听、说、澄清和表达，元枢负责协调与执行；
通话不是一次性派单，不等待任务完成才继续聊，也不替换文字主模型。
以一个持续对话会话统筹多个项目任务；后台按任务隔离执行上下文，不能用同会话互斥限制用户连续交代工作。

三种路线：
- 继续语音转文字、完整生成、全文朗读：复用最多，但不能解决逐段等待。
- 实时语音 + 项目任务组协调（采用）：持续对话、历史检索与执行解耦，复用任务和权限体系。
- 实时模型直接开放全部电脑工具：权限面大、执行记录分裂，本轮不采用。

## 当前证据与接入点

- 当前配置已有 stepfun-plan / stepaudio-2.5-realtime。
- 2026-09-27 使用现有密钥连接 Plan 实时端点，收到 session.created 和
  session.updated；仅证明鉴权和配置成功，未证明音质、工具调用或手机延迟。
- 官方资料：https://platform.stepfun.com/docs/zh/step-plan/integrations/audio-api.md
- 通道：wss://api.stepfun.com/step_plan/v1/realtime?model=stepaudio-2.5-realtime。
- 现有 engine/run-manager.mjs 按 sessionId + clientRequestId 去重并持久化 run；
  同会话另有活动任务时返回 session_busy。
- engine/run-api.mjs 已提供受理回执、进度、事件、停止与恢复能力。
- engine/tui-bridge.mjs 已有独立 WebSocket 路径，可以并存；不改变 TUI 行为。
- 现有朗读属于独立功能；通话期间暂停朗读，防止两路声音同时播放。
- AIBody runtime 当前负责状态、协调提示和事件观察，不是通用跨项目调度器；不能直接宣称它已经具备项目集群能力。
- delegate_task / delegate_fork 当前仅分析给定文本，不读文件、联网或执行命令。
- team-subagents 当前为有依赖的 IDEA→CHALLENGE→EXEC→REVIEW 流程，不等于独立项目并行执行。
- tool-scheduler 有单轮工具并发控制，但不是跨 run 的全局资源锁与项目调度器。

## 第一版范围

### 1. 通话与上下文

从当前会话主动点击开始，进入连接中、聆听、回应、重连提示、已结束或错误状态。
提供静音、打断和挂断；默认温柔女声音色，当前候选 linjiajiejie，需实际试听确认。
不开启自动接听，不在页面载入时索取麦克风权限。

通话绑定当前会话 ID。服务端提供同一小语人设和有限的当前会话上下文，
启动上下文只包括近期消息、明确引用的项目/文件与关联任务摘要，不自动扫描整个工作空间。
用户问“上次那个问题”时，允许在该用户有权访问的历史任务/项目索引中定向检索；
先返回标题、时间、状态、证据链接，必要时再取命中记录的有限正文；不把所有历史灌进模型。
历史摘要不代表当前状态，查询结果附更新时间；同名候选无法唯一匹配时先澄清。
“刚才那个”不能唯一定位时先澄清。切换聊天页面不暗中切换通话绑定对象。
通话记录单独记录，只有明确派单要求进入独立任务执行上下文，避免并行任务覆盖主对话历史。
派单、查询和后台结果都不结束通话；查询耗时长时先告知正在查，用户仍可继续讲话。
后台结果进入带序号的通知队列，用户停顿时简短汇报；不打断用户，不重复播放已播报结果。

开始前明确提示：声音和必要上下文发送给阶跃，并消耗通道额度。
默认不保存原始录音。转写、任务要求和回执按现有会话的查看/删除规则保存。
第一版不承诺离开页面、手机锁屏或系统挂起后继续采音；中断时停止采音并显示实际状态。
已经受理的元枢任务不依赖通话连接，可继续后台执行。

### 2. 受控派单

只向实时模型暴露历史检索、提交任务组、查询任务组、修订指定任务和请求停止的受控函数，
不开放 shell、文件写入、凭据读取、权限调整或任意 HTTP 转发。
具体供应商工具协议由适配层转换，必须用实际工具事件验证，不能仅凭文档视为可用。

提交任务组接收多条明确任务要求和受限引用标识；项目归属由服务端验证，独立执行会话
由协调层建立并关联主对话；工作区、引擎、模型与权限不能由实时模型伪造。
明确的普通工作指令可直接派单，讨论想法不自动执行；不确定意图先问清楚。
高风险行为继续走现有执行侧人工批准，不能把模型生成的“用户同意”当作批准凭据。

登记成功必须返回持久化的 taskId、groupId、status；收到真实登记回执后才能显示“已受理”。
排队任务尚未创建执行 run 时不伪造 runId；开始执行后再关联真实 sessionId、runId。
“已受理”不等于“开始执行”，更不等于“已完成”。完成播报只能来自任务终态及实际产物。
拒绝、超时或未知状态显示具体原因，不编造进度。

用户一次交代三四件事，协调层立即逐项登记并返回接收结果，不要求用户等前一件结束。
每项工作有独立执行会话，继续保留底层每个执行会话单 run 的约束。
独立任务可并行；冲突或依赖任务自动排队，明确说明原因，不让用户逐项点击继续。
修改已有任务必须指定任务 ID 与修订版本：未开始可更新；执行中记录待应用修订，
仅执行器明确确认安全边界接收后才标“已应用”。没有热修改能力时安全停止并建立后继 run，
先核对已发生的副作用；状态不确定则暂停该任务请用户确认，不能盲目重跑。

### 3. 去重与恢复

服务端为每次有效用户指令及任务项建立稳定 handoffId，持久化工具 callId、指令摘要、
taskId、目标会话及实际创建后的 runId 映射。登记与启动分阶段持久化，恢复时对账补齐映射。
使用该 handoffId 构造 clientRequestId，复用现有任务去重。
同 callId 重放返回原回执；同 ID 不同内容拒绝。重连先对账，不自动重新派单。
不能只用提示词相同判断重复：用户明确要求“再做一次”时应新建指令 ID。
并发提交、受理后回执丢失、服务重启都纳入验证；状态不确定时先查询，禁止盲目重试。

通话关闭只释放麦克风、播放器、供应商连接和监听，不调用任务停止。
“停止说话”只打断声音；“停止这个任务”定位任务后走停止请求。
“第二个先别做”等明确且目标唯一的普通停止指令可请求停止；目标含糊或整组停止先澄清。
回执显示“已请求停止”，执行器确认终态后才显示“已停止”；停止不代表撤销已发生的改动。

### 4. 项目任务组与 AIBody 协调

层级为主对话→任务组→项目任务→执行 run→有界子智能体；项目可跨多次通话延续，
一次通话也可涉及多个项目，不强行把所有事情塞进一个工程目录。
这里的“项目集群”是逻辑上的项目与任务协调，不要求部署多台服务器。
持久化字段包含 conversationId、groupId、projectId、taskId、runId、parentTaskId、
依赖关系、资源范围、需求修订版本、状态、证据引用和播报游标。
工作状态与验收状态分开：模型说完成不能自动变成用户已验收。

保留 AIBody 原有身份、记忆、情绪和治理职责；新增协调模块负责需求拆分、
依赖调度、预算与资源仲裁，将真实事件回接 AIBody。执行状态仍以任务存储为唯一事实源，
不在 AIBody 看板再维护一份互相矛盾的任务状态。

初始默认最多两个重执行任务同时运行，并对全系统子调用设置共享并发预算；
为语音和短查询预留容量，防止任务越开越多挤死通话。更多请求立即登记并自动排队。
不同项目也可能竞争同一目录/仓库/部署服务/设备；按实际资源而非项目名加锁。
同仓库修改使用隔离 worktree 或串行执行，合并、构建线上目录、部署与重启由单一受控入口串行处理。
资源范围不明但执行器能强制限制在项目内的命令按项目独占处理；无法限制作用范围的命令
进入全局独占执行或等待批准，不能仅凭模型自行声称“不冲突”放行。

子智能体按能力使用：现有分析/规划/审查子代理继续有界委派；实际改文件、
运行工具与生成媒体由隔离的元枢执行工作者负责，不能假装现有文本 delegate 有这些能力。
每个工作者继承必要的身份约束、任务目标和相关证据，不复制全部私有历史、不扩大权限。
协调层统一回收证据、检验结果、汇报失败。保留父子链、真实模型、工具和产物记录。
复杂任务可以拆分，不给简单查询硬套天团全套流程；有依赖的阶段不得为了并行而破坏顺序。

### 5. 前端呈现

聊天页增加独立通话入口，通话面板上方为状态、音量反馈和控制按钮，下方为任务卡片。
任务卡片按项目分组，显示运行/排队/等待依赖/待批准/待验收/失败及具体原因；
提供查看结果、跳转执行详情和批准入口，用户不必打开多个聊天窗口来管理任务。
窄屏用紧凑抽屉/面板，不遮住挂断按钮，不另造庞大控制台。
保持原有打字、语音转文字输入和朗读入口可用；麦克风不可被两个功能同时占用。
挂机后任务卡保留在会话中。断线不显示“还在听”，重连要重新确认音频链路就绪。

## 技术边界

- 服务端新增独立实时语音桥、工具交接模块及必要的持久化映射；避免扩大 server.mjs。
- 前端分离通话状态、音频采集/播放、界面三个职责，沿用现有主题和按钮规范。
- 浏览器连本服务，服务端再连阶跃；供应商 key 永不进入前端、URL、日志或错误正文。
- WebSocket 校验允许的 Origin，沿用服务认证且限定首包认证超时；认证前不连供应商。
- 仅允许受控音频/会话事件；客户端不能通过原始 session.update 注入工具或覆盖人设。
- 限制同时通话数、帧大小、发送速率、音频队列和连接时长；第一版每个登录实例
  最多一个活动通话，每次上限 25 分钟，到期提示重拨，不影响任务。
- 实际 PCM 采样率、输入/输出格式和事件名称以官方协议及实测为准；浏览器音频需
  显式重采样，不能把设备原始采样率假定为服务要求值。
- 打断时停止本地已排队声音，并按协议取消供应商响应/处理已播放长度；
  迟到音频按响应 ID 丢弃，不让模型误以为用户听完了未播放内容。
- 文本回复、媒体生成和执行引擎事实继续分别记录，实时语音模型不覆盖任务模型身份。
- 通道错误明确展示，不静默切换模型、不无限重连；断开后不缓存上传静音期间的声音。

## 实施顺序

1. 先单独落实协调底座：任务组、历史检索、独立工作者、能力匹配、共享预算、资源锁与恢复。
2. 用文字入口验证连续交代四件事、查询旧任务、修改其中一件、失败隔离和统一回报。
3. 接服务端实时桥与音频：鉴权、事件白名单、资源清理、异步工具回执、权限、打断和回声控制。
4. 联调持续通话及多任务，记录延迟、并发和实际任务结果，再部署；不能把只派一单当本需求交付。

## 验收门槛

- 自动化：未授权连接、错误 Origin、异常帧、越权跨会话查询被拒；授权历史检索可用，密钥不泄漏。
- 自动化：重复事件/并发请求/丢失回执只产生一次任务；内容冲突拒绝；重启可对账。
- 自动化：挂断不终止任务，拒绝权限不执行；多项工作立即登记并按资源调度，不把排队显示成运行中。
- 自动化：打断后没有旧音频继续播放，录音/朗读互斥；关闭后计时器和音频资源释放。
- 真实模型：说一句短话立即获得流式音频；实际函数调用派发一个隔离工作空间的
  小型写文件任务，查询进度，挂机后核对文件和任务终态；不拿真实工作产物当测试靶子。
- 手机和桌面：真实设备权限、扬声器回声、弱网及打断实测；自动化不冒充真人麦克风实测。
- 协调验收：持续通话 5–10 分钟，先查旧任务，再交代四项工作（两项独立、一项依赖、一项同资源冲突），
  中途修改一项、取消一项、让一个子代理失败并断线重连；观察其他任务与对话不被拖死。
- AIBody 验收：需求不漏登、事件不重放执行、跨项目不串素材、历史回答有来源、修订有应用回执、
  冲突无并发写、真实子任务可追踪、失败如实汇报；逐项检查事件链和产物，不用角色称呼冒充协调能力。
- 记录停止说话到首段可听音频的耗时、派单回执耗时；样本不足不宣称固定低延迟。
- 跑 npm run verify、针对改动组件的 Impeccable 检查以及浏览器流程；保留既有失败和
  新增失败的区别，未全绿如实说明。只有联调通过才升级版本和部署。
- 重启前检查活动任务；双推和客户端重打包在交付阶段按实际改动及用户授权执行。

## 本轮不做

电话网络拨号、来电推送、锁屏持续通话、自动接听、语音克隆、开放电脑权限、
自动更换文本主模型、多工作者无锁写同一历史或工作树、无预算限制扩散子任务、未授权自动生成付费媒体。

## 审查结果

V2 替代 V1 的“同会话忙碌则只存草稿”方案；保留底层互斥，通过独立执行上下文支持多项工作。
允许基于用户问题定向检索授权历史，不是无差别跨会话取材。通话、协调与执行生命周期分离。
现有 AIBody 与 delegate 的能力限制已明确；协调底座是需要建设和验收的能力，不是配置即得。
代码实现尚未开始，当前线上版本保持不变。
