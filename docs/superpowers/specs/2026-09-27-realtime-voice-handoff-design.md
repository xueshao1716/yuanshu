# 小语实时通话与元枢任务交接

日期：2026-09-27
状态：设计已整理，待用户审阅；不是已上线能力。

## 目标与选择

用户已认可分工：阶跃实时模型负责听、说、澄清和派单，元枢负责执行；
通话不是第二套拥有电脑权限的执行引擎，也不替换文字主模型。

三种路线：
- 继续语音转文字、完整生成、全文朗读：复用最多，但不能解决逐段等待。
- 实时语音 + 受控任务交接（采用）：对话与后台执行解耦，复用任务和权限体系。
- 实时模型直接开放全部电脑工具：权限面大、执行记录分裂，本轮不采用。

## 当前证据与接入点

- 当前配置已有 stepfun-plan / stepaudio-2.5-realtime。
- 2026-09-27 使用现有密钥连接 Plan 实时端点，收到 session.created 和
  session.updated；仅证明鉴权和配置成功，未证明音质、工具调用或手机延迟。
- 官方资料：https://platform.stepfun.com/docs/zh/step-plan/integrations/audio-api.md
- 通道：wss://api.stepfun.com/step_plan/v1/realtime?model=stepaudio-2.5-realtime。
- 现有 engine/run-manager.mjs 按 sessionId + clientRequestId 去重并持久化 run；
  同会话另有活动任务时返回 session_busy。
- engine/run-api.mjs 已提供受理回执、进度、事件、停止与恢复能力。
- engine/tui-bridge.mjs 已有独立 WebSocket 路径，可以并存；不改变 TUI 行为。
- 现有朗读属于独立功能；通话期间暂停朗读，防止两路声音同时播放。

## 第一版范围

### 1. 通话与上下文

从当前会话主动点击开始，进入连接中、聆听、回应、重连提示、已结束或错误状态。
提供静音、打断和挂断；默认温柔女声音色，当前候选 linjiajiejie，需实际试听确认。
不开启自动接听，不在页面载入时索取麦克风权限。

通话绑定当前会话 ID。服务端提供同一小语人设和有限的当前会话上下文，
只包括近期消息、明确引用的项目/文件与关联任务摘要；不自动扫描其他会话或整个工作空间。
“刚才那个”不能唯一定位时先澄清。切换聊天页面不暗中切换通话绑定对象。
通话记录单独记录，只有明确派单要求进入任务执行上下文，避免与执行中的文字历史互相覆盖。

开始前明确提示：声音和必要上下文发送给阶跃，并消耗通道额度。
默认不保存原始录音。转写、任务要求和回执按现有会话的查看/删除规则保存。
第一版不承诺离开页面、手机锁屏或系统挂起后继续采音；中断时停止采音并显示实际状态。
已经受理的元枢任务不依赖通话连接，可继续后台执行。

### 2. 受控派单

只向实时模型暴露 submit_task、get_task_status 和 request_task_stop 三个受控函数，
不开放 shell、文件写入、凭据读取、权限调整或任意 HTTP 转发。
具体供应商工具协议由适配层转换，必须用实际工具事件验证，不能仅凭文档视为可用。

submit_task 接收明确任务要求和受限引用标识；会话、工作区、执行引擎与模型由服务端
绑定的会话配置确定，不接受模型自行指定的权限、路径范围或伪造会话。
明确的普通工作指令可直接派单，讨论想法不自动执行；不确定意图先问清楚。
高风险行为继续走现有执行侧人工批准，不能把模型生成的“用户同意”当作批准凭据。

派单成功必须有真实 runId、sessionId、status；收到回执后才能显示“已受理”。
“已受理”不等于“开始执行”，更不等于“已完成”。完成播报只能来自任务终态及实际产物。
拒绝、超时或未知状态显示具体原因，不编造进度。

同会话忙碌时返回 session_busy 和活动任务卡片；不绕过互斥，不自动另起会话。
第一版将补充要求保存为“尚未提交”，等任务结束后由用户点击继续提交；
不宣称具备运行中热修改任务能力。本限制在界面明示。

### 3. 去重与恢复

服务端为每次有效用户指令建立稳定 handoffId，持久化工具 callId、指令摘要、
目标会话及 runId 映射。使用该 handoffId 构造 clientRequestId，复用现有任务去重。
同 callId 重放返回原回执；同 ID 不同内容拒绝。重连先对账，不自动重新派单。
不能只用提示词相同判断重复：用户明确要求“再做一次”时应新建指令 ID。
并发提交、受理后回执丢失、服务重启都纳入验证；状态不确定时先查询，禁止盲目重试。

通话关闭只释放麦克风、播放器、供应商连接和监听，不调用任务停止。
“停止说话”只打断声音；“停止这个任务”定位任务后走停止请求。
第一版停止任务需界面确认，回执显示“已请求停止”，终态到达再显示“已停止”。

### 4. 前端呈现

聊天页增加独立通话入口，通话面板上方为状态、音量反馈和控制按钮，下方为任务卡片。
任务卡片展示真实状态、简短进度、查看结果、跳转会话，以及需要时的批准入口。
窄屏用紧凑抽屉/面板，不遮住挂断按钮，不另造庞大控制台。
保持原有打字、语音转文字输入和朗读入口可用；麦克风不可被两个功能同时占用。
挂机后任务卡保留在会话中。断线不显示“还在听”，重连要重新确认音频链路就绪。

## 技术边界

- 服务端新增独立实时语音桥、工具交接模块及必要的持久化映射；避免扩大 server.mjs。
- 前端分离通话状态、音频采集/播放、界面三个职责，沿用现有主题和按钮规范。
- 浏览器连本服务，服务端再连阶跃；供应商 key 永不进入前端、URL、日志或错误正文。
- WebSocket 校验允许的 Origin，沿用服务认证且限定首包认证超时；认证前不连供应商。
- 仅允许受控音频/会话事件；客户端不能通过原始 session.update 注入工具或覆盖人设。
- 限制同时通话数、帧大小、发送速率、音频队列和连接时长；第一版每个登录实例
  最多一个活动通话，每次上限 25 分钟，到期提示重拨，不影响任务。
- 实际 PCM 采样率、输入/输出格式和事件名称以官方协议及实测为准；浏览器音频需
  显式重采样，不能把设备原始采样率假定为服务要求值。
- 打断时停止本地已排队声音，并按协议取消供应商响应/处理已播放长度；
  迟到音频按响应 ID 丢弃，不让模型误以为用户听完了未播放内容。
- 文本回复、媒体生成和执行引擎事实继续分别记录，实时语音模型不覆盖任务模型身份。
- 通道错误明确展示，不静默切换模型、不无限重连；断开后不缓存上传静音期间的声音。

## 实施顺序

1. 先测试后实现任务交接：真实回执、归属校验、幂等、忙碌、停止、断线与重启恢复。
2. 接服务端实时桥：鉴权、事件白名单、资源清理、工具回调与进度回传。
3. 接手机/桌面通话入口及音频：权限、播放解锁、静音、打断、回声控制、失败提示。
4. 联调真实阶跃模型和隔离元枢任务，记录延迟及实际任务结果，再部署。

## 验收门槛

- 自动化：未授权连接、错误 Origin、异常帧、跨会话查询被拒；密钥不泄漏。
- 自动化：重复事件/并发请求/丢失回执只产生一次任务；内容冲突拒绝；重启可对账。
- 自动化：挂断不终止任务，拒绝权限不执行；忙碌时不新建任务，不把未提交显示成运行中。
- 自动化：打断后没有旧音频继续播放，录音/朗读互斥；关闭后计时器和音频资源释放。
- 真实模型：说一句短话立即获得流式音频；实际函数调用派发一个隔离工作空间的
  小型写文件任务，查询进度，挂机后核对文件和任务终态；不拿真实工作产物当测试靶子。
- 手机和桌面：真实设备权限、扬声器回声、弱网及打断实测；自动化不冒充真人麦克风实测。
- 记录停止说话到首段可听音频的耗时、派单回执耗时；样本不足不宣称固定低延迟。
- 跑 npm run verify、针对改动组件的 Impeccable 检查以及浏览器流程；保留既有失败和
  新增失败的区别，未全绿如实说明。只有联调通过才升级版本和部署。
- 重启前检查活动任务；双推和客户端重打包在交付阶段按实际改动及用户授权执行。

## 本轮不做

电话网络拨号、来电推送、锁屏持续通话、自动接听、语音克隆、开放电脑权限、
自动更换文本主模型、多任务并行改同一会话、运行中热修改任务、自动生成付费媒体。

## 审查结果

已明确任务事实来源、上下文范围、权限、幂等与手机限制；没有将连通性测试写成通话验收。
第一版“运行中补充要求”只保留草稿，不谎报执行；后续若需要即时补充，另做执行侧协议。
代码实现尚未开始，当前线上版本保持不变。
