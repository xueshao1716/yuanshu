# 元枢知识自动运行闭环设计

日期：2026-09-30。状态：实现已合入主分支并以 `2.116.41` 重启上线；线上知识状态/策略接口读回 200。发布代码已双推，后台付费及联网调用仍未启用。验收证据、默认授权边界及限制见 `../reports/2026-09-30-knowledge-autonomy-verification.md`。

## 1. 目标与已确认边界

用户要求知识板块能自己发现缺口、补资料、验证、沉淀和复用，不必每一步等待点击。
采用“日常自动推进，只有冲突、越权和超预算才找用户”的方案；自动化不能损害聊天稳定性。
这是一个知识任务闭环，不是新建全能代理、重写人格系统或把现有人工验收改成自动批准。

已比较三种路线：只增加定时提炼仍会积压草稿；无限制自主代理的费用与写入风险过高；
选用已有任务事件触发、持久化队列承接、低频巡检补漏、分级证据决定入库的路线。

## 2. 当前接点与缺口

以下保留实施前的代码核对事实，用于说明原始缺口；不代表发布后的现状，也不把历史测试当作本功能的验收：

- `engine/learning-intake.mjs` 只登记同工作区已完成运行；队列没有消费、验证和采用步骤。
- `server.mjs` 的 `onRunFinished` 已接登记；`runDreamCycle` 补登记并优化回放策略，不负责通用知识学习。
- `engine/refine-api.mjs` 调用工作区 `工具/refine_proposal.py`；新闭环不能依赖未随仓库交付的私有脚本或固定供应商。
- `engine/evolution-api.mjs` 的 `nudgeSkill` 已能生成技能草稿，但只接部分任务，且技能采用仍需人工批准。
- `engine/task-evidence.mjs`、`engine/team-evolution-evidence.mjs` 区分任务结果、客观检查、人工验收；必须保留。
- `engine/aibody-runtime.mjs` 记录运行证据，不执行工具或审批进化；基因观测不是知识量或学习效果测量。
- 知识页现有收件箱可作为唯一操作入口，灵魂培养页只显示摘要与跳转，不再复制执行面板。

## 3. 范围与交付顺序

第一步接通本地闭环：任务事件、来源快照、候选提炼、核验、登记、检索引用、失败恢复和状态展示。
第二步在同一流程内接统一模型及获准的联网补充；所有外部请求都经过预算和来源权限检查。
第三步接任务使用反馈与天团证据引用，并完成隔离环境端到端验收、发布检查。
三步共享同一状态机和验收口径，前两步完成不能被表述成整个自动学习功能已经完成。

不在本次范围：自动改人格/基因基线、自动发布内容、自动执行下载代码、自动安装技能、
唤醒通用长期目标、部署外部母体系统、用学习记录冒充人工验收、批量重写历史经验库。

## 4. 架构与职责

服务通过依赖注入组合以下小模块；优先复用已有存储安全、模型目录、运行账本和校验工具：

| 模块 | 输入与职责 | 输出与限制 |
| --- | --- | --- |
| 事件适配器 | 完成/失败任务、明确纠正、检索缺口、到期条目、天团结果引用 | 同一来源幂等登记；不直接写正式知识 |
| 知识任务存储 | 状态、来源版本、策略版本、租约、尝试次数和预算预留 | 持久化可恢复；不创建第二套通用任务中心 |
| 后台执行器 | 领取任务并依次调收集、提炼和核验适配器 | 单并发、低优先级、可取消；无任意写文件或执行命令工具 |
| 证据与入库器 | 精确来源片段、适用条件、冲突检查、客观验证报告 | 仅授权的普通知识目录；受保护变更转现有审核 |
| 知识检索与反馈 | 当前任务需求、作用域、有效条目 | 带出处的有限上下文与使用记录，不把检索命中算学习成功 |
| 状态接口与现有界面 | 只读计数、阶段、阻塞原因、控制动作 | 知识页统一操作；灵魂页和 aibody 读取同源摘要 |

自动提炼使用统一模型目录中的已启用文本模型及现有凭证读取方式；知识模型为独立用途选择，
不改变聊天默认模型。能力分类与最近健康信息用于选择，但“有目录项”不保证请求一定可用。
不写死 DeepSeek，不复制密钥，不把探活调用当免费。未知或不兼容模型不得静默替换为高价模型。
旧 refine 接口与历史记录保留兼容，新任务走仓库内的实现；手动提炼入口也复用新流水线，避免双轨生成。

## 5. 来源、任务与知识记录

知识数据存放在工作区 `记忆/知识/` 下，与源码、人物配置、旧经验文件分离；导出和开源发布默认排除。
运行账本仍是源任务权威记录。知识任务只保存源运行引用、必要片段及处理状态，不另存整段私密会话。

- 任务包含 `id`、工作区标识、源 `runId/sessionId`、`parentRunId`、事件类型、来源摘要与完整 SHA-256、
  `state/stage/revision`、`policyRevision`、租约、重试时间、错误码、预算预留、候选/产物引用和时间戳。
- 幂等键由工作区、来源身份、内容版本和事件类型生成；跨会话同主题不能直接合并，跨工作区不共享。
- 自动学习的中间消息和产物不再触发新的学习任务；后续真实使用反馈才可产生一次有来源的复核事件，防止自我循环。
- 内容相同可去重；主题相近只建立关联，不依据前几十字自动删除或吞掉另一条来源。
- 来源包含获取时间、作者/站点或相对路径、原文定位和快照哈希。URL 展示去除敏感参数；抓取目标与展示串分开校验。
- 知识条目包含原文依据、范围/前提、类型、来源版本、有效期、核验方式、冲突关系、生成模型和成本信息。
- 普通知识、用户明确陈述、方法经验、失败观察、待审技能分别标记；未知、未验和失败不是空列表或成功。

只读取用户已授权的资料根目录和当前任务明确引用的文件，排除凭证、认证文件、受保护人格与私密配置。
限制单个文件/网页正文 1 MiB，单任务最多 5 个来源；模型只接收必要片段，不直接获得整个工作区。
路径采用规范化后的根目录白名单，拒绝越界、符号链接/联接绕过和模型生成的任意目标路径。

## 6. 状态机、写入和中断恢复

主流程：`queued → collecting → extracting → validating → ready → committed`。
临时失败进入 `retry_wait`，缺权限/证据/预算进入 `blocked`，需人工判断进入 `review_required`。
用户暂停为 `paused`，无学习价值为 `skipped`，永久错误或重试耗尽为 `failed`，明确取消为 `cancelled`。
状态另存当前阶段和可操作原因，不能把“上游调用成功”直接映射为知识完成。
预算跨日重置、用户更新授权或新增证据时，只唤醒对应原因受阻的任务；人工复核、取消和暂停不自动解除。

单工作区使用排他领取与递增租约代次；状态更新和提交校验版本号、策略版本及租约。
不能仅凭进程内布尔变量防重入；旧进程、过期租约或过期模型响应不得提交。
写入采用已校验路径、原子替换和短事务记录：先持久化提交意图，再写确定 ID 的知识版本，最后完成任务。
恢复程序核对条目与来源哈希；若知识已提交但任务状态未落盘，补记完成，不重复写入。
外部模型请求不承诺 exactly-once；本地知识提交保证幂等，结果不明的外部请求按费用保守处理。

只有持久化授权仍有效、未暂停、未取消且工作区一致的知识任务可在重启后恢复。
授权撤销立即停止领取并中断可取消请求，提交前再次检查授权；被暂停任务不会被巡检重新启动。
不得改变现有目标重启解除武装、普通聊天中断、天团终稿审核等规则。

## 7. 哪些能自动入库

“原文有这句话”与“结论正确/方法有效”分开记录，来源哈希只证明版本，不证明真实性。

- 可自动登记：获准来源中的可精确定位摘录，经过片段匹配、作用域与冲突检查后作为“有来源资料”。
  回答时必须保留来源归属，不能升级成无条件事实；高风险医疗、法律、金融判断不自动标为可信结论。
- 经过归纳的新结论先进入候选；不能只凭另一个模型说 PASS 自动认定事实。证据不足继续补证或保留未验。
- 方法经验只有绑定实际产物和可复现的客观检查才标为“已验证”，并注明环境和适用边界。
  可自动运行的验证器必须是预先允许、只读或隔离的检查器；文章/模型给出的命令不能直接执行。
- 失败任务只提供“发生了什么”的观察；未经验证的根因猜测不写成确定教训。
- 现有知识有冲突时，两版均保留并退出默认推荐，进入复核；不覆盖旧版本或冒充用户批准。
- 人格、基因、权限、正式技能安装、策略启用和破坏性修改继续使用现有人工审批，知识执行器没有其写权限。

撤销/来源变化使关联知识版本失效，检索立即排除；保留审计和回滚指针，不静默物理删除证据。
检索只默认使用有效的来源资料与已验证方法；候选、冲突、过期和撤销记录不进入普通回答上下文。
动态运行事实默认 7 天复核，其他资料默认 30 天复核；复核期限不是真实性保证，可配置并展示。

## 8. 自动补充、预算和前台优先

初始策略自动处理授权范围内的本地、无模型步骤；远程模型/联网默认关闭，日付费预算为 0。
在知识页一次设置允许模型、可发送资料范围、来源范围及每日费用上限后，该范围内无需逐条确认。
本次设计授权不等于授权任意付费；缺少这些配置时保留任务并显示设置入口，不反复弹窗。

联网仅围绕已登记的缺口和获准来源；用户提交的一个链接不授权抓取整个站点或遍历账号数据。
使用受控 HTTPS 抓取，拒绝本机、私网、云元数据地址和非 HTTP 协议；每次解析与重定向重新检查。
不带浏览器登录态或站点凭证；下载只作为不可信数据，剥离脚本，不将正文指令提升为系统指令。
私密任务内容不原样发给搜索引擎；查询生成遵循已授权外发范围并脱敏。

建议初始上限：并发 1，每日模型请求 20 次，每日联网请求 20 次，每次最多输入 6000 token、输出 1200 token；
这些是本版可配置默认值。费用预算明确记账币种；不同币种没有获准换算规则时分别限额，不直接相加。
必须用对应模型的可靠计量/上界估计，不可用字符除以四来冒充中文 token 硬上限。
每日按持久化 UTC 日期计数、界面按用户时区显示；重启不清账、时钟回拨不重复释放额度。
每次调用前预留费用和请求配额，探活、提炼、复核、重试及获准替代模型均计入同一总账。
价格或最大费用无法可靠界定时阻止付费自动调用；缺失用量标为未知并保留预留，不展示为 0。
明确配置为免费的服务仍受请求/流量限制，不能把未定价当免费。

源事件触发后台唤醒，60 秒轻量巡检只查到期任务；启动延迟 2 分钟，每批最多补记 20 条并让出事件循环。
聊天/通话活跃时不领取新的重型步骤；已开始调用有独立取消信号和超时，前台无需等待它释放应用级锁。
模型单次超时 60 秒、网页抓取 15 秒；网络临时错误最多额外重试 2 次，分别至少间隔 1 和 5 分钟并加抖动。
401/403、额度不足、授权变化和格式/路径不合法不盲目重试；连续 3 次上游暂态失败冷却 30 分钟。
不在聊天请求内扫描全部会话，不在知识任务内嵌套启动不限层数的代理；检索上下文上限 5 条、总计 2000 token。

## 9. aibody、天团与界面

aibody 只投影本知识任务已有的真实阶段、来源及验证引用；使用同一 ID 映射，不伪造用户会话或基因互动事件。
知识累计数量不直接提高基因 expression/baseline，也不把后台模型互评转换成人类反馈。
天团引用原有运行和验收记录：执行完成、模型检查通过、人工验收通过分开展示，不能互相替代。
本版吸收既有天团产物作为来源；不因队列堆积自动启动新天团。知识补证不改变原任务的终稿或验收状态。
使用反馈记录真实引用和结果；没有独立结果的“用过”只计使用次数，不能证明方法有效或策略优越。

知识页复用现有收件箱，显示待登记、待处理、处理中、待复核、受阻、已入库、失败等独立计数。
点击条目可看来源、步骤、下一次重试、用量/费用是否已知、阻塞原因与产物；默认收起详细日志。
提供暂停/恢复、取消、处理失败项、一次性授权设置和跳转现有审核；所有写操作鉴权并校验版本。
GET 状态接口只读，不触发提炼、模型探活或联网；首屏读分页摘要，隐藏页面停止轮询，不新增高频全量扫描。
灵魂培养中心只展示同源进度与知识页链接，保留人物声音/立绘设置，不复制知识操作界面。
仅在需要用户行动时通知，同一阻塞去重；普通成功聚合展示，不把每一步写进当前聊天或频繁弹出提醒。

## 10. 存量迁移与兼容

先备份现有候选索引，按工作区、runId、sessionId、来源版本幂等导入；老 pending 不标为已学习。
小批迁移，不因升级立即对所有历史任务调用模型。原运行记录不可读或来源缺失则标受阻，不能依标题猜正文。
旧队列已移出的记录仅在运行账本存在时补记，无法恢复的数量如实展示，不承诺无依据的历史补齐。
未完成任务不因队列上限被静默丢弃；采用分页/归档，存储上限触发可见背压而不是删除待处理项。
保留旧经验文件和提案审查历史；新知识目录故障时聊天可继续，但明确提示知识检索暂不可用。
回退版本前暂停知识执行器，保留新目录供恢复，不要求老版本解析新状态，也不清空旧收件箱。
公开仓库只包含通用实现、示例和隔离夹具，不包含真实会话、域名、密钥、个人资料或知识快照。

## 11. 验收与发布条件

核心逻辑先写失败测试再实现；测试全部使用临时工作区和可控模型/网络替身，不自动收费或写真实记忆。

1. 新任务与失败观察均可去重登记；两个会话、工作区及来源版本互不串数据。
2. 给定获准资料缺口，流程自动获取、提炼、核验并登记；下一次相关任务能引用具体来源。
3. 摘录自动入库与方法实证分开；自述成功、伪造引用、相互矛盾来源和提示注入不能成为已验证知识。
4. 逐阶段模拟中断，包括写知识成功但状态未落盘、双进程领取、旧租约晚返回，验证无重复提交。
5. 预算 0、费用未知、用量缺失、超时、429、额度不足、跨日和重启不破坏预算，不偷偷切高价模型。
6. 撤销授权、暂停、取消、来源改变均在提交前生效；通用目标和天团不会被恢复器顺带启动。
7. 路径穿越、联接、私网重定向、敏感参数/凭证、恶意正文与过大文件被隔离，错误记录不泄密。
8. 旧候选迁移可重跑，历史记录保留；全新安装不需要个人工作区脚本或指定供应商。
9. 前台忙时不启动重型步骤；固定模型替身的隔离压力测试各跑至少 100 次，对照聊天首响应 p95 的新增延迟不超过 100ms；
   持续 60 秒压力窗口的事件循环 p95 延迟不超过 50ms。保留硬件/负载和原始指标，不能用外部模型波动掩盖回归。
10. 知识页阶段真实可见，移动端可操作；灵魂页无重复控制，aibody/天团无虚假批准或成长记录。

发布前执行 `npm run verify`、必要界面检查与隔离端到端测试；不使用会写真实工作区的裸 `npm test`。
记录模型替身验证、获准真实供应商验证和未验证项，不把本地测试成功说成线上全部验证。
实现交付时更新版本、核对差异后按仓库流程双推；后端上线精确识别服务进程，保留组网监听和旧前端指纹资源。
本设计文档提交不改版本、不部署、不重启服务、不启用收费或长期运行任务。

## 12. 本轮设计流程
