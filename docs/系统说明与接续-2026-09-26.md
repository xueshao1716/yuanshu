## 2. 系统结构与部署入口

- `server.mjs` 是服务入口；`engine/`、`lib/` 承载运行与接口模块。元枢自制循环、pi SDK 等路径不能混为一个权限执行面。
- 当前 React 前端源码在 `frontend/src/`，服务读取 **`frontend/dist/`**，不是 `public/`。隔离验证构建输出在 `tmp/verification-dist/`，该目录存在不代表已上线。
- 服务端模块改动需要重启。标准入口：`powershell -NoProfile -ExecutionPolicy Bypass -File D:\pi-web\scripts\restart-pi-web.ps1`。该入口可能要求真实系统提权；拒绝时停止，不绕过。
- 重启会中断流式会话，必须先检查活动任务。不要为验收清空线上旧指纹资源，避免已打开页面加载失败。
- 桌面壳和手机壳目前读取服务页面；纯 Web 更新在实际部署后重新加载可见。原生桥、权限、壳配置及安装包版本的更新仍需重新打包与验收，不能把源码版本同步称为安装包已更新。

## 3. 超维模式：本轮实际完成

1. 沙箱接口必须指定真实会话；缺失或未知会话拒绝，不再回退到最近会话。
2. 前端缓存、组件状态和异步保存按会话隔离，补齐忙碌锁、错误与重试，避免 A 会话结果污染 B。
3. API 操作来源如实记录为 API，不把普通请求当成人工认证。
4. 维护授权纯协议默认 3600000ms、最大 7200000ms；校验会话、任务、运行、主体、执行器、策略、epoch、动作摘要、版本、时钟与有效期。终态不可复活，不自动续期。
5. 超维说明面板显示不可用原因；未开放启用按钮。生产申请接口固定拒绝并返回 `503 executor_unavailable`，不存在租约的撤销返回 404，不虚报成功。

**还不能让元枢取得完整电脑权限或实际改自己。** 尚缺可信本机人工批准、签名与防重放、真正的操作系统隔离执行器、受保护持久审计、进程树撤销、受控发布与恢复。现有纯协议测试不等于这些能力已实现。没有 grant/renew、环境变量绕过、无限 shell 或手机提权入口；pi SDK 路径不自动受此模式覆盖。
