# 智能体培养：部署与日常操作

培养空间位于「灵魂养成 → 智能体培养」。它展示真实设计、任务、学习证据与资源授权。
安装功能不会自动授权付费、生成角色、启动远程任务或修改母体人格与基因。
初始状态为预算 0、远程关闭、等待小语提交真实设计。

## 主人授权通道

访问令牌只用于登录，不能证明操作者是主人。策略修改、暂停、恢复、取消、回退和
人工向母体共享学习成果需要单次命令签名；母体自主采用须先由主人签名开启下述授权。
服务只保存公开凭据，模型不能在 HTTP 中登记密钥。

### Windows 桌面：本人确认

1. 安装 2.116.46 或更新的 Windows 客户端，并连接本机工作台。
2. 打开「灵魂养成 → 智能体培养 → 授权与资源」，点击「检查本机确认方式」。
   若提示 Windows Hello 不可用，到 Windows 设置 → 账户 → 登录选项设置 PIN 或指纹。
3. 点击「设置本人确认」，核对系统窗口并亲自完成 Windows Hello。配对只登记当前
   Windows 账户的本机公开凭据，不开启学习、不生成个体、不授予预算。
4. 点击「核对七天受限学习」，阅读范围，再点击「本人确认并执行」。本人确认成功后
   自动提交并重新读取状态，不需要复制密钥或签名。请求 60 秒有效，取消或到期不会执行。
5. 如显示提交结果待核对，关闭确认区并刷新记录，不重复提交。可用「暂停全部培养与学习」
   核对并停止后续采用；暂停本身同样需要本人确认。

此预设七天有效，仅允许采用所属个体有独立来源且已核查的培养经验；每日请求和费用
上限均为 0，模型、工具和调度窗口为空，外网关闭，不读取私人记忆、不改写人格或基因。
没有合格经验时保持等待。它不是自动生成或自动批准证据的循环，也不代表学习已经发生。

公开凭据保存在 `%LOCALAPPDATA%/Yuanshu/owner-confirmation/<工作区摘要>.json`；私钥由
Windows 验证器管理。服务与客户端应使用同一个 Windows 账户。网页、旧客户端、远程工作台
和非 Windows 客户端不提供本机配对。外部签名配置优先，不会静默改成 Windows Hello。

凭据丢失、损坏或替换后，当前服务进程锁定通道并废除未用请求；恢复文件不会自动解锁。
需要本人核对宿主配置后重启，不能通过网页自动重置。可信文件属于本机部署边界，不能防御
已能任意改写服务或用户文件的恶意本机进程。页面模拟测试不等于真实 Hello 或硬件兼容性验收。

### 高级方式：独立 Ed25519 签名

1. 主人在自己控制的可信设备准备 Ed25519 密钥；私钥不要放在仓库、业务工作区、
   网页、聊天或模型能读取的目录。工程交付不会替用户生成真实身份。
2. 主人或可信运维将 SPKI 公钥文件放到服务宿主的绝对路径，文件不能是链接。
   配置 `YUANSHU_CULTIVATION_HUMAN_PUBLIC_KEY_FILE` 及
   `YUANSHU_CULTIVATION_HUMAN_ACTOR`，然后重启服务。
3. 在可信终端独立核对业务工作区 realpath 的 SHA256（Windows 先转小写），记录此值。
   不要直接信任待签名请求里自报的工作区。
4. 面板选择操作，核对内容后生成授权请求，把 JSON 保存到可信设备的临时文件。
   请求 30 秒有效，可重新生成；只有签名助手读取私钥。
5. 运行 `node scripts/cultivation-sign.mjs WORKSPACE_SHA256 ABS_PRIVATE_KEY ABS_REQUEST_JSON`。
   助手会校验目标、内容摘要、有效期并显示完整命令；必须亲自键入显示的确认语。
6. 将输出的一次性签名粘贴回面板。提交异常先刷新核对，不盲目重试。

密钥轮换需替换宿主配置并重启；旧请求、跨工作区请求、过期或重复签名均拒绝。
本通道不能防御已经能任意改写服务代码或读取主人私钥的宿主管理员。

## 授权与模型

培养和知识后台共用请求、费用与并发账本；前台聊天优先。两处授权都必须满足：
知识模型白名单与价格配置，以及培养策略的模型、日请求、日预算、有效期和调度窗口。
`expiresAt` 是 ISO 日期字符串，不是毫秒数。金额上限为美分；未知用量保留预留，不能算 0。
无法确定价格或令牌上限的模型不派发；本阶段仅支持明确输入的文字任务，不继承工具、
私人记忆或 computer-use 权限，也不支持再繁殖。

## 学习与停止

任务输出只形成有来源的假设；失败、取消、未完成和中断的任务留下执行记录，中断结果按未知处理。
执行状态不证明原因或知识正确性，原始私密错误不写入经验正文。到知识页面补充独立来源并完成审阅，
再决定采用或退役。个体只能采用自己范围内的补证，采用与退役保留版本、理由和身份。

母体学习有两条明确分开的授权路径：

- 主人对单条补证签名分享给母体。
- 主人在培养策略中签名启用 `motherLearning: true`（默认关闭），允许母体自行决定采用所属、就绪个体的
  有独立来源的经验。培养策略与个体设计均须含 `knowledge:approved-cultivation` 数据范围；每次仍核查
  当前身份、来源、授权有效期与个体状态，不跳过知识审阅，也不允许母体给自己授权。

关闭 `motherLearning` 后不再取用自主采用的经验；主人逐条签名的分享不受此开关影响。
停用培养策略会停止两类分享。历史对话不会删除，已经发出的内容不能撤回。
目前采用保守的控制版本绑定：策略、设计或个体操作使控制版本变化后，旧自主采用记录仍在，
但必须重新核验并采用才可再用；单纯重新打开开关不能恢复旧决定。

普通文本聊天仅在真实母体执行身份下取用与当前问题相关的已采用知识，最多五条，受现有字节预算限制。
提供给模型不算使用，回复中实际出现对应知识引用才记引用次数；引用也不证明效果或用户认可。
这不是无人值守的自动补证／批准循环，本批也未接入语音、媒体或 DSH 路径。
不自动更改基因、人设、情绪或工具权限，模型自评不等于用户接受。

暂停阻止后续派发并请求取消在途任务。未确认结束显示等待或结果待核对。
重启不重放未知请求，不清预算，也不自动恢复暂停。遇到「结果待核对」应先核查
模型服务端实际用量；不要通过删账本或重复提交绕过预留。
