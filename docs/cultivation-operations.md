# 智能体培养：部署与日常操作

培养空间位于「灵魂养成 → 智能体培养」。它展示真实设计、任务、学习证据与资源授权。
安装功能不会自动授权付费、生成角色、启动远程任务或修改母体人格与基因。
初始状态为预算 0、远程关闭、等待小语提交真实设计。

## 主人授权通道

培养策略支持已登录用户的当前会话确认（安卓、网页和桌面均可），包括开启、续期和
暂停全部培养。它是明确的产品信任边界：持有登录凭据、能访问该会话的用户可以确认
具体策略，但不等于硬件验证的主人身份。记录标为 `session-confirmed-user`，不会冒充
Windows Hello 或独立签名。请保护工作台登录凭据；本通道无法防御已控制服务宿主的进程。

个体恢复、取消、回退和人工向母体逐条分享学习成果仍使用原有单次命令签名。
会话通道仅允许 `policy.set`，不会同时开启电脑操作、文件或其他系统权限。
母体自主采用须先由用户明确确认开启下述授权，模型不能自行批准或登记密钥。

### Windows 桌面：本人确认

1. 安装 2.116.46 或更新的 Windows 客户端，并连接本机工作台。
2. 打开「灵魂养成 → 智能体培养 → 授权与资源」，点击「检查本机确认方式」。
   若提示 Windows Hello 不可用，到 Windows 设置 → 账户 → 登录选项设置 PIN 或指纹。
3. 点击「设置本人确认」，核对系统窗口并亲自完成 Windows Hello。配对只登记当前
   Windows 账户的本机公开凭据，不开启学习、不生成个体、不授予预算。
4. 点击「核对七天受限学习」，阅读范围，再点击「本人确认并执行」。本人确认成功后
   自动提交并重新读取状态，不需要复制密钥或签名。请求 60 秒有效，取消或到期不会执行。
5. 如显示提交结果待核对，关闭确认区并刷新记录，不重复提交。可用「暂停全部培养与学习」
   核对并停止后续采用；暂停本身同样需要本人确认。

此预设七天有效，仅允许采用所属个体有独立来源且已核查的培养经验；每日请求和费用
上限均为 0，模型、工具和调度窗口为空，外网关闭，不读取私人记忆、不改写人格或基因。
没有合格经验时保持等待。它不是自动生成或自动批准证据的循环，也不代表学习已经发生。

公开凭据保存在 `%LOCALAPPDATA%/Yuanshu/owner-confirmation/<工作区摘要>.json`；私钥由
Windows 验证器管理。服务与客户端应使用同一个 Windows 账户。网页、旧客户端、远程工作台
和非 Windows 客户端不提供本机配对。外部签名配置优先，不会静默改成 Windows Hello。

凭据丢失、损坏或替换后，当前服务进程锁定通道并废除未用请求；恢复文件不会自动解锁。
需要本人核对宿主配置后重启，不能通过网页自动重置。可信文件属于本机部署边界，不能防御
已能任意改写服务或用户文件的恶意本机进程。页面模拟测试不等于真实 Hello 或硬件兼容性验收。

### 安卓、网页与桌面：培养策略的会话确认

1. 打开「灵魂培养中心 → 智能体培养 → 授权与资源」，在上方选择真实已有会话。
2. 在「让她开始培养一个智能体」中选择小语已提交的设计，点击「核对七天受限培养」。
   预设会替换原策略：七天、最多一个个体、每天一次请求、每天最多 50 美分；仅使用该
   设计的精确模型标识，不开放工具、递归繁殖、私人记忆或母体自主采用。
3. 核对完整策略，点击「本次会话确认并执行」，亲自确认弹窗。无需 Windows 设备配对。
   60 秒内的确认绑定工作区、会话、完整命令和版本，只能使用一次；取消、过期、会话
   不可用或撤销均不能提交。切换会话或离开确认页面会作废尚未提交的确认。
4. 成功后重新读取记录，再让小语读取 overview。若旧设计 `remote:false`，小语可在
   完整权限与新策略匹配时，仅修订 `remote:true`，再登记新版本。`tools:[]` 是当前文本
   执行器的正常设计，不需要给个体补工具。
5. 若显示「提交结果尚待核对」，刷新记录核查版本，不重复提交。暂停全部培养也能用
   本通道确认；其他个体或资源操作仍在设备与签名设置中进行。

开启策略和登记个体不自动发模型请求。付费任务仍须明确提交，并满足知识后台授权、
共享资源账本、价格与额度；本预设不修改这些独立约束。原有「仅采用已核查经验」是另
一个零费用预设，不会开启培养运行，选择时请注意两者区别。

会话弹窗使用现有服务端确认登记表；挑战请求本身不算批准。安卓原生生物识别不会被
伪装为服务端签名。现有客户端加载服务器工作台，纯网页修复重新载入即可；真实手机
兼容性应单独验收，模拟手机宽度的页面测试不等于实机验证。

### 高级方式：独立 Ed25519 签名

1. 主人在自己控制的可信设备准备 Ed25519 密钥；私钥不要放在仓库、业务工作区、
   网页、聊天或模型能读取的目录。工程交付不会替用户生成真实身份。
2. 主人或可信运维将 SPKI 公钥文件放到服务宿主的绝对路径，文件不能是链接。
   配置 `YUANSHU_CULTIVATION_HUMAN_PUBLIC_KEY_FILE` 及
   `YUANSHU_CULTIVATION_HUMAN_ACTOR`，然后重启服务。
3. 在可信终端独立核对业务工作区 realpath 的 SHA256（Windows 先转小写），记录此值。
   不要直接信任待签名请求里自报的工作区。
4. 面板选择操作，核对内容后生成授权请求，把 JSON 保存到可信设备的临时文件。
   请求 30 秒有效，可重新生成；只有签名助手读取私钥。
5. 运行 `node scripts/cultivation-sign.mjs WORKSPACE_SHA256 ABS_PRIVATE_KEY ABS_REQUEST_JSON`。
   助手会校验目标、内容摘要、有效期并显示完整命令；必须亲自键入显示的确认语。
6. 将输出的一次性签名粘贴回面板。提交异常先刷新核对，不盲目重试。

密钥轮换需替换宿主配置并重启；旧请求、跨工作区请求、过期或重复签名均拒绝。
本通道不能防御已经能任意改写服务代码或读取主人私钥的宿主管理员。

## 授权与模型

保存设计草稿不启用策略，也不创建可执行个体，这是有意分开的边界。
登记、采用、恢复和回退个体仍须满足启用状态、有效期、模型／工具／数据授权以及资产、
归属等检查；但不再要求运行额度大于零。可表达“允许个体存在，暂不允许运行”。
仅当提交或执行任务时才检查次数和费用，零额度不能绕过执行检查。

执行时，培养和知识后台共用请求、费用与并发账本；前台聊天优先。两处授权都必须满足：
知识模型白名单与价格配置，以及培养策略的模型、日请求、日预算、有效期和调度窗口。
`expiresAt` 是 ISO 日期字符串，不是毫秒数。金额上限为美分；未知用量保留预留，不能算 0。
无法确定价格或令牌上限的模型不派发；本阶段仅支持明确输入的文字任务，不继承工具、
私人记忆或 computer-use 权限，也不支持再繁殖。

### 操作诊断与被拒记录

「授权与资源 → 操作检查与近期拒绝」按登记、提交或执行分别检查配置，一次列出阻碍、
对应字段和处理建议。提交可以排队，执行则必须位于授权时段。预检不会修改授权、
生成个体、预留费用或探活模型；通过不代表最终身份、设计关系、并发名额或实际费用通过。
状态版本变化后需重新检查，不应循环重试同一个被拒请求。

母体工具有三个只读动作，已登录 HTTP 客户端也可读取对应接口：

- `models` / `GET /api/cultivation/models`：返回精确 `provider/id` 标识，区分培养与共享
  白名单，并标注 `health: not_checked`。不要把目录存在、授权和探活混为一谈。
- `preflight` / `GET /api/cultivation/preflight?action=agent.register&designId=<实际UUID>`：
  登记用真实设计编号；`run.submit`、`run.dispatch` 用真实 `agentId`。工具调用将查询放在
  `payload` 中。返回 `blockedBy`、`nextAction`、`checkedAt`、`revision` 和只读检查范围。
- `denials` / `GET /api/cultivation/denials`：读取近期已识别身份、未被接受的操作。

例如目录返回 `example-provider/example-text` 时，设计 `permissions.model` 和两处授权
都应使用该完整标识；这只是格式示例，不能照抄作为本机合法模型。实际值必须读取目录。

被拒记录独立存放，最多保留 200 条、页面显示最近 20 条。同一请求及相同错误合并计数；
不保存正文、令牌或原始异常，不改变策略版本，也不计为模型调用。损坏记录不会显示为
成功读取的空历史。伪造或无法识别的身份不进入此业务记录；已接受后执行失败仍查任务
时间线，因此空拒绝列表不能证明从未失败。错误响应通过 `audit.recorded` 明确是否记录成功。

## 知识纠错与回声控制

自动提取会跳过明显的模型进度闲聊。自动检索不把同会话中未经独立验证的纯模型输出
再次注入给自己，也跳过遗留进度闲聊及带知识引用的纯模型回声。显式按知识编号检查仍
保留原文与来源；来源权限、有效期和字节上限照常检查。过滤是保守启发式，不是真伪裁判。
过期的未验证纯模型片段退出检索，不以同一任务重新入队来伪装成新证据；不删除历史。

知识页面可对“已入库”任务提交更正来源。新来源先形成待核查记录，不能直接覆盖原文。
仅在审阅及后续来源、授权、版本复核通过后替代旧条目；旧条目保留为已被替代的历史。
拒绝、保留原文或授权撤销都不替换原条目，也不把模型自述升级为已验证事实。

## 学习与停止

任务输出只形成有来源的假设；失败、取消、未完成和中断的任务留下执行记录，中断结果按未知处理。
执行状态不证明原因或知识正确性，原始私密错误不写入经验正文。到知识页面补充独立来源并完成审阅，
再决定采用或退役。个体只能采用自己范围内的补证，采用与退役保留版本、理由和身份。

母体学习有两条明确分开的授权路径：

- 主人对单条补证签名分享给母体。
- 用户在培养策略中明确确认启用 `motherLearning: true`（默认关闭），允许母体自行决定采用所属、就绪个体的
  有独立来源的经验。培养策略与个体设计均须含 `knowledge:approved-cultivation` 数据范围；每次仍核查
  当前身份、来源、授权有效期与个体状态，不跳过知识审阅，也不允许母体给自己授权。

关闭 `motherLearning` 后不再取用自主采用的经验；主人逐条签名的分享不受此开关影响。
停用培养策略会停止两类分享。历史对话不会删除，已经发出的内容不能撤回。
目前采用保守的控制版本绑定：策略、设计或个体操作使控制版本变化后，旧自主采用记录仍在，
但必须重新核验并采用才可再用；单纯重新打开开关不能恢复旧决定。

普通文本聊天仅在真实母体执行身份下取用与当前问题相关的已采用知识，最多五条，受现有字节预算限制。
提供给模型不算使用，回复中实际出现对应知识引用才记引用次数；引用也不证明效果或用户认可。
这不是无人值守的自动补证／批准循环，本批也未接入语音、媒体或 DSH 路径。
不自动更改基因、人设、情绪或工具权限，模型自评不等于用户接受。

暂停阻止后续派发并请求取消在途任务。未确认结束显示等待或结果待核对。
重启不重放未知请求，不清预算，也不自动恢复暂停。遇到「结果待核对」应先核查
模型服务端实际用量；不要通过删账本或重复提交绕过预留。
