# 智能体培养：部署与日常操作

培养空间位于「灵魂养成 → 智能体培养」。它展示真实设计、任务、学习证据与资源授权。
安装功能不会自动授权付费、生成角色、启动远程任务或修改母体人格与基因。
初始状态为预算 0、远程关闭、等待小语提交真实设计。

## 主人授权通道

访问令牌只用于登录，不能证明操作者是主人。策略修改、暂停、恢复、取消、回退和
向母体共享学习成果需要单次命令签名。服务只保存公钥，模型不能在 HTTP 中登记密钥。

1. 主人在自己控制的可信设备准备 Ed25519 密钥；私钥不要放在仓库、业务工作区、
   网页、聊天或模型能读取的目录。工程交付不会替用户生成真实身份。
2. 主人或可信运维将 SPKI 公钥文件放到服务宿主的绝对路径，文件不能是链接。
   配置 `YUANSHU_CULTIVATION_HUMAN_PUBLIC_KEY_FILE` 及
   `YUANSHU_CULTIVATION_HUMAN_ACTOR`，然后重启服务。
3. 在可信终端独立核对业务工作区 realpath 的 SHA256（Windows 先转小写），记录此值。
   不要直接信任待签名请求里自报的工作区。
4. 面板选择操作，核对内容后生成授权请求，把 JSON 保存到可信设备的临时文件。
   请求 30 秒有效，可重新生成；只有签名助手读取私钥。
5. 运行 `node scripts/cultivation-sign.mjs WORKSPACE_SHA256 ABS_PRIVATE_KEY ABS_REQUEST_JSON`。
   助手会校验目标、内容摘要、有效期并显示完整命令；必须亲自键入显示的确认语。
6. 将输出的一次性签名粘贴回面板。提交异常先刷新核对，不盲目重试。

密钥轮换需替换宿主配置并重启；旧请求、跨工作区请求、过期或重复签名均拒绝。
本通道不能防御已经能任意改写服务代码或读取主人私钥的宿主管理员。

## 授权与模型

培养和知识后台共用请求、费用与并发账本；前台聊天优先。两处授权都必须满足：
知识模型白名单与价格配置，以及培养策略的模型、日请求、日预算、有效期和调度窗口。
`expiresAt` 是 ISO 日期字符串，不是毫秒数。金额上限为美分；未知用量保留预留，不能算 0。
无法确定价格或令牌上限的模型不派发；本阶段仅支持明确输入的文字任务，不继承工具、
私人记忆或 computer-use 权限，也不支持再繁殖。

## 学习与停止

任务输出只形成有来源的假设；到知识页面补充独立来源并完成审阅，再决定采用或撤回。
个体只能采用自己范围内的补证；跨入母体须主人明确签名。采用与撤回保留版本、理由和身份。
不自动更改基因、人设或情绪记录，模型自评不等于用户接受。

暂停阻止后续派发并请求取消在途任务。未确认结束显示等待或结果待核对。
重启不重放未知请求，不清预算，也不自动恢复暂停。遇到「结果待核对」应先核查
模型服务端实际用量；不要通过删账本或重复提交绕过预留。
