# 元枢长任务自动接续验收（2.115.6）

## 事故证据

用户报告采集任务停在“单次输出被截断……回我一句分块写”。实际运行记录
`eec1dc16-a8a6-4dc1-8e26-0df2f4c8cc41` 已执行到第 20 轮工具调用。
旧代码在工具循环耗尽后把中间文本包装成输出截断错误，还会进入模型兜底，
因此该错误文案不能证明模型真的触及输出 token 上限。

## 修复行为

- 普通工具任务每 20 轮检查进展，仍有成功执行的工具则沿用同一模型、历史、
  检查点和防循环状态继续；单次调用最多 60 轮。显式轮数限制和生图专用限制保留。
- 工具轮数耗尽返回 `tool_turn_limit`，明确任务未完成，保留已完成结果；
  不再因此进入输出截断的模型兜底。手动恢复沿用原轮次编号，并获得新的有界预算。
- OpenAI `length` 与原生 Messages `max_tokens` 触发最多两次自动分块恢复。
  完整工具结果保留，半截参数不执行，纯文本从断点接续；最终失败也保留最后一段。
- 单次输出预算受模型声明及剩余上下文约束，未取消供应商上限。
- 错误提示不再要求用户回复“分块写”，也不再无条件声称模型已被冷却。
- 批量采集恢复提示要求分页、限速、断点续传脚本直接落盘，只返回数量、路径和校验摘要。
