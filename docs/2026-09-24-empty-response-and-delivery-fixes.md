# Fable 空回复恢复与交付检查修正

## 范围

本轮优先处理已复现的承诺统计误算、交付验收误放行，以及元枢空回复恢复丢失工具上下文的问题。没有实施全部 11 项建议；没有修改默认引擎或 Fable 的接入协议。

## Fable 5.1：事实与修复

- 当前配置是 `aieyra-claude/claude-fable-5-1`，走 OpenAI 兼容接口。代码已有 Anthropic Messages 分支，不能沿用早期“只有 chat/completions”的判断。
- 运行 `31343968-fdfc-49f7-a313-d9a32db23fcf` 记录了主模型连续空回复、切换 agnes 备用模型、备用模型执行多轮工具后仍空回复。原来已有切换提示，但失败发生前没有及时发出 `model_switched`。
- 同一模型第一次空流式回复后，改用非流式重试；仍限制为两次重试。有效工具调用会重置连续空回复计数，不因不同阶段偶发空回复过早耗尽预算。
- 切备用模型沿用本轮最新历史，保留工具结果。备用模型失败也保留其工具轨迹和具体错误；切换事实在备用请求开始前发给界面，并保存在适用的会话元数据中。
- 增加 `model_empty_response` 运行事件：请求与实际模型、重试次数、SSE/JSON、结束原因、正文/思考长度和 token 用量。事件不包含用户正文、密钥或原始请求。
- 删除原来位于空回复 return 之后、无法覆盖空回复故障的临时诊断分支。

真实模型验证：简单问答、带工具请求、历史上下文重放、历史上下文加工具表均获得有效返回；另用元枢真实循环执行合成 `lookup(alpha)=17`、`lookup(beta)=25`，Fable 两次工具调用后返回 `TOTAL=42`，未切换模型。历史重放只解析返回，不执行模型给出的工具；完整循环只运行合成查询，不修改用户工作产物。

边界：历史失败没有保存原始空响应，无法确证当时的上游原因。当前成功不代表所有长会话必然成功，本轮解决的是确定存在的恢复与诊断缺陷。

## 交付验收

`python scripts/verify_delivery.py <文件或目录> --json [--width 736 --height 1312] [--ratio 0.666667]`

- 图片须完整解码，可校验指定尺寸/比例；只打开文件头不算通过。
- 视频须有解码器并完成帧解码；缺依赖标 `unverified`，不再当作成功。此检查不验证音轨、剧情或指定目标时长。
- HTML 检查基础结构与直接相对本地资源；缺资源失败。静态检查通过仍标 `unverified`，不能替代浏览器运行、CSS 引用或远端资源验收。
- 缺文件、空目录、坏文件失败；不支持格式仅记录存在性与摘要，标 `unverified`。
- `status` 为 `passed`、`failed`、`unverified`。`valid` 仅在 `passed` 时为 true，全部文件 passed 才返回退出码 0。
- 本机兼容入口 `D:/pi-workspace/工程/_scripts/verify_delivery.py` 已更新。脚本没有自动接管所有聊天交付，也不会只凭存在性自动写入“验收通过”标记。
