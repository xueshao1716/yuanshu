## 2. 关键发现：不能把旧实现直接搬进来

### A1. 模型扫描不是实际探活

`A/symbiosis-middleware/model-health-monitor.js:24-53` 的 `scan` 通过模型 ID 是否包含 `UNAVAILABLE` 或 `DISABLED` 决定 `ok/failed`，没有向模型端点请求。它另有 `markFailure` 接受真实失败输入；这不改变 `scan` 本身为模拟判断的事实。

结论：拒绝移植这一扫描。Y 的 `engine/model-probe.mjs` 已区分目录发现、名称推断与用户主动触发的实际文本验证；目录中出现不等于可调用。本轮没有发起任何模型验证请求。

### A2. 默认分数与固定阈值不能当作生态健康事实

`A/symbiosis-middleware/persona-governor.js:19-47` 使用默认 0.5、固定权重及 0.52/0.72 阈值分配角色状态，还包含旧人格默认值。`evolution-lineage.js` 的谱系记录有参考价值，但其 fitness 默认值、加权分和 mutation 代数不是元枢真实成长证据。

结论：只吸收来源链、版本关系的理念；不导入默认人格、健康分、角色晋升阈值或自动变异策略。

### B1. 防同质化统计有边界，不是人格诊断

`B/src/anti_homogenization.rs:18-39,73-127` 对六组关键词统计，以全部文本为分母，同一文本可以计入多个主题；超过 40% 即提示。它截取部分内容、没有时间窗或最小样本条件，目录读取失败也可能表现为零样本。默认路径还指向其他旧系统目录。

结论：保留“观察分布及重复来源”的思路；不复制旧路径、关键词分类和 40% 红线。工作任务暂时集中于修复，不足以推出情绪或人格退化。元枢没有合格的个体级情绪样本时，应显示未观察。

### C1. 三条自动提案分支均被自身门槛挡住

`C/01-理论/original/evolution.py:29-39,61-107` 中，提案变化小于 0.01 即返回；三个自动分支的最大增量却分别为 0.005、0.008、0.005。即使 growth 条件满足，这三条分支也无法生成提案。

本轮用 AST 只抽取这两个函数，以三项 growth 均满足、baseline 均为 0.5 的合成数据运行，结果为 0 条提案、0 次 I/O。没有导入或启动原脚本。

`approve_proposal:110-158` 还未检查 pending 状态、证据有效性和当前基线版本，直接使用提案旧值建立快照。不能用它替换 Y 已有的证据、过期基线及人工确认机制。

### C2. 去重与过时判断只能当候选提示

`C/01-理论/original/dreaming.py:67-115` 只比较前 200 字符，超过 0.8 就标记合并，并取第一条全文为 best；过时判断仅检查“临时/暂时/待修复”等词，没有核对后续更新或时效。

本轮只抽取去重函数，输入共同前缀 200 字符、尾部事实互相不同的两条合成记录，仍得到合并候选并保留第一条。原 `dream` 只保存报告，不应误报它已经自动删除了原记忆。

结论：可以吸收“整理先产候选、不覆盖原始证据”；不能把相似片段视为事实等价。Y 的来源哈希、到期复核和替代记录优先，不再建立另一套记忆真相库。

### C3. 旧会话清理存在数据丢失风险

`C/01-理论/original/vassal_audit.py:78-120` 对未知/普通会话按闲置时间调用归档再删除。`_archive_gene:125-144` 最多复制前 50000 个字符且吞掉部分归档异常；调用方不检查归档是否成功，随后 `_delete_session_file:147-153` 可继续删除原文件。

这是静态代码确认的风险，未对真实会话执行。高级等级分支实际只归档，不能仅根据注释声称它也会删除。

结论：不移植自动清理、截断备份或等级治理。任何后续保留策略都需独立授权、可验证备份及恢复方案。

## 3. 与元枢现状的取舍矩阵

| 机制 | 元枢已有依据 | 决策 |
| --- | --- | --- |
| 设计谱系、独立培养对象 | `engine/cultivation/designs.mjs`、`control-transition.mjs` | 复用当前设计版本与身份，不导入旧角色 |
| 模型探活 | `engine/model-probe.mjs`、`model-verification.mjs` | 不重复；拒绝名称模拟探活 |
| 基因提案与回滚 | `engine/gene.mjs`、`gene-evidence.mjs`、`gene-approval.mjs` | 不替换；保留证据、版本与人工批准 |
| 知识整理、更新复核 | `engine/knowledge-maintenance.mjs` | 不另建做梦写入器；现有授权下按来源与时效复核 |
| 子体经验反哺 | `engine/knowledge-cultivation.mjs`、`knowledge-cultivation-learning.mjs` | 不重复；模型输出是候选，母体采用走人工授权 |
| 来源链的可读呈现 | `engine/cultivation/experience.mjs`、前端 `Learning.tsx` | 首批补齐观察呈现，保留同一事实来源 |
| aibody 土壤及表达分布 | `engine/aibody-soil.mjs`、`cultivation/projection.mjs` | 保留母体/会话/孩子边界；不从母体快照推导孩子状态 |
| 自动评分、按等级清理、旧运行态 | 现有生态规格不允许以假证据替代治理 | 明确不吸收 |

当前 `projection.mjs:24` 的 observations 仍为 `not_observed`，资源页也明确尚无独立土壤结论；这是观察能力未补齐，不能美化成已经具备完整健康评估。

`experience.mjs` 的 `evidenceCount:0` 指模型输出本身不能提供独立证据；补证与采用在关联记录里。不能为了数字好看把字段加一，或把 resolution 的存在当作来源当前仍有效。

## 4. 推荐路线及替代方案

1. **推荐：沿现有链补齐证据观察。** 范围小、可逐项验收，不改权限、调度、基因和学习规则。具体提案见同日设计草案。
2. **只保留研究档案。** 无新增运行风险，但培养面板的可理解性缺口仍在。
3. **整体导入旧母生态或运行时桥。** 可同时获得较多旧功能，但身份、持久化、权限及重复队列的冲突面大；不属于本轮授权，不采用。

分布观察、记忆整理候选属于后续候选，不与首批捆绑；真实人格、情感表达与培养方法仍由小语提交设计。
