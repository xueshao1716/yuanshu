## 本批：请求解析和缓存边界

### 1. 中文与表情被网络分块损坏

根因：`readBody` 把每块 Buffer 独立转成字符串。UTF-8 字符跨块时被替换为乱码，JSON仍可能解析成功，因此内容会无声损坏。

修正：使用 Node 内置 StringDecoder 跨块解码；按原始字节累计请求体大小，在累积内容前检查上限。保留空请求体、非法JSON的400，以及超限时排空剩余请求并返回413的既有约定，不主动毁掉连接。

回归：遍历中文、表情、中文路径JSON的每一个两段切分点；验证恰好达到字节上限能通过、多一个字节返回413。

### 2. 缓存规则污染接口和错误响应

根因：入口包裹所有响应的 `writeHead`，仅根据URL后缀/目录强制缓存。实测 `/api/private.png` 的401响应带 `public, max-age=31536000, immutable`；无版本人像、图标和缺失资源也被一年强缓存。

修正：移除入口中的缓存覆写器；默认 `no-store`，由成功的静态文件服务设置具体缓存规则。保留HTML、service worker、无指纹资源的 `no-cache` 重验证；带构建指纹的 assets 文件和现有版本查询参数继续长期缓存，304保持一致。鉴权、CSP、路由注册与签名文件流程不变。

回归：用真实本地HTTP运行生产请求回调，覆盖401、已授权私有API、缺失指纹资源404、普通图片/图标、现行人像路径、HTML、构建指纹资源200与304。无模型、任务或真实工作空间副作用。
