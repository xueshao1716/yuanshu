# 她怎么跟你说话：主动推送这一套

> 这份文档解释元枢（小语）**主动找你**时说的话是怎么来的、哪些是硬规则、出问题去哪查。
> 对应代码：`engine/notice-voice.mjs`、`engine/wechat-push-format.mjs`、`engine/companion-nudge.mjs`、`server.mjs`（`maybe*Brief`）。

## 一、四种推送，什么时候来

| 类型 | 什么时候 | 一天几次 | 数据从哪来 |
|---|---|---|---|
| **离开提醒** | 你 45 分钟没出现，且距上次提醒超 3 小时 | 不固定 | 你的「最后一次出现时间」 |
| **晚间复盘** | 23:00 之后 | 1 次 | 今天动过的会话数 + 经验库今天的条目 |
| **0 点反思** | 0:00–2:00 | 1 次 | 夜里跑一次进化/做梦，取回放条数与新策略 |
| **晨报** | 08:00 之后 | 1 次 | 待办件数 + 第一条 + 昨天沉淀 |

规则细节：

- **深夜不吵**：离开提醒在 0–6 点不主动发（除非你正好在）
- **一天只发一次**：三种简报各自记 `记忆/运行时/简报.json`，发过就不再发
- **没数据不发空话**：0 点反思如果回放 0 条、也没新策略，那天就不推（仍然记为"发过"，避免反复跑）
- **免打扰优先**：面板里开了免打扰，离开提醒直接不发

## 二、话是谁写的

**是她自己写的**，不是查表拼字符串。流程：

```
事实（几件事、几条经验、回放多少条、离开多久）
  ↓
写作要求（第一人称、40 字内、最多一个 emoji、一眼看出发生了什么）
  ↓
她写一版
  ↓
三重校验 ── 不过 → 带着"上次哪里不行"重写一次
  ↓                       ↓
通过                   还不过 → 用兜底话术（人写的固定句子）
```

兜底话术长这样：

- 离开：「你走了 49 分钟，我这边的活还留着，回来接着做？」
- 晚间：「今天的活我过了一遍，明天能省点事。」
- 反思（有数据）：「夜里回放 42 条轨迹，v3 更稳，明天按这个来。」
- 反思（0 条）：「今天轨迹不够，没做结论，明天接着看。」
- 晨报：「早，今天要做的事我列好了。」

## 三、硬规则（这些是拦在发送前的）

### 文本规则

1. **不超过 80 字、最多 3 行**
2. 不许出现「元枢」「详情在元枢」「作为AI」
3. 必须一眼看出发生了什么（数字 / 时间 / 动作词三者至少一个）
4. 最多一个 emoji

### 编造规则（真机上抓到过，才加的）

| 场景 | 她写错过 | 现在拦法 |
|---|---|---|
| 离开提醒 | 「搞定了，报告已经交上去了」——根本没这回事 | `away` 类不许出现「报告/交上去/已完成/搞定/睡」这类无依据成果词 |
| 0 点反思 | 「刚复盘发现一处关键遗漏，已沉淀修正方案」——那次回放 0 条 | 回放 0 条时不许说「发现/遗漏/梳理出/沉淀出/修正/关键」，也不许说「沉淀 N 条」；但「没做结论」这种否定表述放行 |
| 任意 | deepseek 把「我们需要回答…」整段思考当正文 | 以推理语气开头直接判死 |

### 语气规则

提示词里写着：**克制、可靠、像靠谱的搭档；可以轻松，但不抱怨、不自嘲、不玩梗。**

拦的例子：「摆烂 / 躺平 / 破事 / 宕机 / 烂透 / 崩了 / 废了 / 自闭」。
真机抓到过「复盘了 101 件破事…明天躺平摆烂 🙃」，现在会被判不合格、重写。

## 四、版式

**正文她写，骨架宿主保证**（这样每一条看起来都像同一个人的手笔，不是每封信重排一次）：

```
💬 晚上 23:10｜小语
━━━━━━━━
今天复盘了两件事，没沉淀出经验。

明天把难点拆细一点。

· 今天 2 件事
· 沉淀 0 条

—— 23:10 · 今晚复盘
```

各部分：

- **抬头**：`图标 + 时段 时间 | 署名`（署名是人设名，从 `记忆/人格定义.json` 读，读不到用「小语」）
- **正文**：她的原话，段落之间空行；只有一句话时不加项目符号（这是她说话，不是清单）
- **数据行**：一条一行（`·` 前缀），前面空一行
- **落款**：`—— 时间 · 这件事是什么`

任务/交付类通知（不是这四种简报）保持要点符号：

```
🗓 海报改完了｜小语
━━━━━━━━
• 尺寸 1080x1440
• 文案已换
—— 23:10 · 交付
```

## 五、安全边界

定时任务（简报、做梦、离开提醒）跑在 `scheduler` 身份下，受动作策略约束：

```json
{ "id": "no-scheduler-external", "initiator": ["scheduler"],
  "deny": ["notify_user", "run_detached"],
  "reason": "定时任务不许自己对外发消息/拉长活" }
```

意思是：**定时任务不能自己决定给你发消息**——它们只能走上面这四条固定链路，且每条都要过编造/语气校验。想让她"随便说点什么"，得是你（`user`）发起的对话。

策略文件 `记忆/运行时/动作策略.json` 可改、可回滚，事务台「动作策略」块里能编辑。

## 六、出问题怎么查

| 想查什么 | 去哪 |
|---|---|
| 最近发了什么通知 | `C:\Windows\system32\config\systemprofile\.pi\agent\notifications.json`（保留最近 100 条） |
| 她为什么退回了兜底 | 服务日志搜 `[notice]`，会打印原因（太长/编造/推理过程…） |
| 定时任务被策略拦了 | `记忆/运行时/动作审计.jsonl` 里 `phase:"denied"` 的行，或 `GET /api/audit/tail` |
| 简报今天发过没有 | `记忆/运行时/简报.json` |
| 想手动触发一次 | `POST /api/brief/night`、`/api/brief/morning`、`/api/brief/reflection`、`/api/companion/nudge`，都支持 `{force:true}` |

## 七、已知限制

1. **数字口径还粗**：晚间「今天 N 件事」= 今天动过的**会话数**，不是任务数；闲聊会话也算一件
2. **反思的策略名是内部 id**（如 `skill-match`、`v3`），不是人话
3. **单评委式写作**：写和校验都是同一族的模型，语气稳定但偶尔会绕
4. **emoji 只限数量不限类型**，还会出现 🫡 🌙 这类偏网络语的符号
5. 简报的**数据行固定三到四个**，不会因为内容少而收起来（0 条也照写，是有意的：不粉饰）
