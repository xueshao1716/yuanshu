# 长任务后台执行验收（2.115.8）

## 问题与修复

聊天前端原先在 10 分钟没有收到 SSE 事件时调用 `RunsApi.stop()`，把前台没有事件误判为服务端任务失活。手机切后台、浏览器节流、SSE 短暂断开、模型深度思考或长工具执行都可能触发这个条件。

2.115.8 将该计时器改为只更新提示条，不改变 Run 状态、不取消工具、不生成失败文案。页面隐藏和订阅关闭仍只影响本端显示，服务端 Run 继续执行；用户点击“停止”仍走显式停止 API。

## 验收证据

- `tests/unit/frontend-structure.test.mjs`：确认空闲计时器没有停止 API，只有手动停止路径调用 `RunsApi.stop()`。
- `tests/unit/run-manager.test.mjs`：取消浏览器订阅不会关闭后台请求或停止 Run，后台请求可继续完成并重放全部事件。
- `tests/unit/run-api.test.mjs`：SSE 断线重连使用事件游标，停止 API 与 SSE 生命周期解耦。
- 页面恢复通过 `visibilitychange`、SWR 重验证和 Run 事件游标补齐正文。
- `tests/e2e/chat-background-task.playwright.mjs`：使用隔离会话/API 夹具和加速时钟，桌面、390px 手机视口模拟后台静默 11 分钟，自动停止请求均为 0；刷新后从已保存游标恢复完成结果，正文只显示一次。第三个场景验证手动停止仍发出一次停止请求。未调用付费模型，也不等同于真机息屏 11 分钟的耐久测试。

## 交付边界

本次改动 Web 前端运行时与版本声明，服务端无须改变执行预算。已验证服务无需重启即可读取新的 `frontend/dist`；已打开的旧页面需刷新才会执行新代码。手机端如果使用嵌入式前端快照，需要另行重新打包才会包含本次前端代码，本次未生成客户端安装包。

`engine/task-continuation.mjs` 保留最长 30 分钟的单次自动执行预算（安全轮次边界检查）。预算到期保存检查点并暂停，可点击“继续任务”；不是无限无人值守执行承诺。服务主机须保持开机、联网，真实模型/工具错误、人工停止、服务重启与前台断连分别处理。
