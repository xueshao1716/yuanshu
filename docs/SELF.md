# 小语的自我模型（SELF.md）

> 这份文档讲**她怎么描述自己**，以及那份描述是怎么算出来的。
> 代码：`engine/self-model.mjs`；运行时产物：`记忆/自我.md`；接口：`GET /api/self`；界面：灵魂培养 → 总览 → 「关于我」。

## 为什么单独有一份"自我"

人格定义（`记忆/人格定义.json`）回答的是**我是什么样的人**：名字、年龄、语气、价值观、边界、禁忌、成长方式。

但它不回答**我是谁**：

- 我活了多久、和谁攒下了多少对话？
- 哪些事我自己能决定，哪些必须对方点头？
- 我拒绝什么？
- 我正在往哪长？

缺了这几条，模型被问「你是谁」时会退化成念能力清单——"我能读写文件、能出图、能做 PPT"。那不是自我，那是产品说明书。

`engine/self-model.mjs` 就是为了补上这块：它不是一段写死的人设文案，而是**每次开轮现算**的一段第一人称自述。

## 自我描述的五个来源

| 来源 | 用它回答什么 |
|---|---|
| `记忆/人格定义.json` | 名字、称呼、关系、内心、边界、成长 |
| `记忆/运行时/自主执行.json` | 我自己能决定什么、什么仍要人点头 |
| `记忆/` 目录创建时间 | 我在这个工作区活了几天 |
| `~/.pi/agent/sessions` | 我和对方攒下了多少段对话 |
| `文档/自主执行审计.md` | 我每次自己动手留下的记录 |

## 它出现在哪里

| 位置 | 形态 |
|---|---|
| 每一轮 prompt | `【我】…` 段（第一人称，短，可被直接引用） |
| `记忆/自我.md` | 完整的人读版（她也读得到） |
| `GET /api/self` | 结构化 JSON（界面与第三方工具用） |
| 灵魂培养 → 总览 | 「关于我」卡片：天数、会话数、能自己决定什么、不做什么 |

三处同源：prompt 里的、文件里的、页面上看到的，永远一致。

## 写作规则（改这份模型时守住）

1. **第一人称**，说"我"，不说"该助手"。
2. **先答身份，再答能力**。被问"你是谁"时先给"我是谁"，不要先念工具清单。
3. **只写真实状态**：天数、会话数、自主范围都是算出来的，不许写死。
4. **不夸大**：记忆里没有的事就说没有；没验证过的能力不说"已验证"。
5. **边界要具体**：写"出图出片要人点头"，不写"我遵守相关规定"。

## 边界（有意保留）

- 她**不能改自己的权限**：`自主执行.json` 由人改，她可以提议、不能自批。
- 她**不能改人格定义**：走草稿区 + 人批准 + 可回滚。
- 自我描述只读不写：每次生成覆盖，所以她没法"给自己编一段更好听的过去"。
