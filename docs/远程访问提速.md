# 远程访问提速：实测数据与可做的选择

> 2026-11-06 · 对象：`pi.myxinyu.xin`（Cloudflare Tunnel 到家里 127.0.0.1:8787）

## 一、实测（从本机打自己的域名）

| 指标 | 数值 | 正常吗 |
|---|---|---|
| DNS | 12ms | ✅ |
| TCP 连接 | 240ms | ⚠️ 跨境基线 |
| TLS 握手 | 490–1990ms | ❌ 太慢 |
| TTFB（HTML） | 1.0–3.3s | ❌ |
| TTFB（静态资源） | 首次 MISS，之后 **HIT（Age: 6）** | ✅ 已缓存 |
| **Tailscale 直连** | **5ms** | ✅ |

**结论：静态资源已经走 Cloudflare 边缘缓存了（`cf-cache-status: HIT`），源站缓存头也是对的（`immutable`）。慢的不是缓存，是“跨境 + 回源隧道”这条路本身。**

Cloudflare 免费版没有中国大陆节点，请求要绕到香港/新加坡/美西再隧回你家，
**每个来回 ≈ 200–400ms**，一次握手要两三个来回。

## 二、能做的（按性价比）

### ① 开 HTTP/3（免费，一分钟）

Cloudflare 后台 → **Network → HTTP/3 (with QUIC)** → 打开。

响应头已经带 `alt-svc: h3=":443"`，说明边缘支持；开着能让手机少一两个握手来回。

### ② Argo Smart Routing（$5/月）

Cloudflare 后台 → **Traffic → Argo**。

它会把流量走更优路径。跨境场景通常能快 20–40%，但**改变不了“绕境外”这个本质**。

### ③ HTML 加短 TTL 边缘缓存（免费，需权衡）

现在 `/` 是 `no-cache`，每次打开都要 2 秒。

Cache Rules 里给 `/` 和 `/index.html` 加：

```
Edge TTL: 30 秒   /   Browser TTL: 0
```

代价：发版后最多 30 秒内可能拿到旧 HTML（但 `assets` 带指纹，旧 HTML 引用的是旧 JS，不会白屏）。
**收益：重复打开从 2.2 秒降到几十毫秒。**

### ④ 换来路（真正解法）

| 方案 | 延迟 | 代价 | 适合 |
|---|---|---|---|
| **Tailscale 直连** | **5ms** | 两端装 App + 登录 | **自己日常用** |
| 国内 ECS + frp | 20–50ms | 服务器钱 + 备案（或非标端口） | 要给别人用 |
| IPv6 直连 + DDNS | 最快 | 等运营商 + 动路由器 | 长远 |

## 三、我的建议

```
自己用        → Tailscale（100.108.182.77:8787，已在系统页集成）
分享给别人    → 域名（能打开就行，不追求快）
真要对外做产品 → 国内 ECS + frp
```

**不要试图用免费 Cloudflare 把国内访问做到“快”**——物理路径决定的，配置改不动。

## 四、顺手可查的一件事

如果是手机 4G/5G 访问慢、家里 WiFi 访问快，那多半是运营商国际出口的问题，
和 Cloudflare 无关。可以用手机流量打开 `https://pi.myxinyu.xin/api/health` 看实际耗时，
和本机对比一下就能确认。
