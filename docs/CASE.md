## 案例 1：把每周的选题会变成一页 PPT（示例结构，待填真实数据）

**谁**：独立开发者 / 小团队（人数）

**原来怎么做**
1. 手动翻素材，挑 6 个选题
2. 写大纲、做 PPT、改三版
3. 人工耗时：__ 小时；每周 1 次

**现在怎么做**
1. 在元枢里说一句：「把这周的素材整理成 6 个选题的一页 PPT，存到交付」
2. 她把成品写到 `交付/`，把过程写进 `文档/`
3. 人工耗时：__ 分钟（其中 __ 分钟是核对）

**产出在哪**：`交付/选题会-YYYY-MM-DD.pptx`

**失败与边界（必填）**
- 什么情况下会失败：模型未配置 / 图源不可用 / 超长素材需要分批
- 需要人介入的环节：选题终审、对外发布
- 已测量的失败率：__%（样本 __ 次）

**可复现命令**
```bash
git clone https://gitee.com/linxinyu520xue/yuanshu.git
cd yuanshu && node setup.mjs --install && node server.mjs
# 浏览器打开 http://127.0.0.1:8787 → 配置模型 → 粘贴上面那句话
```

## 案例 2：让她每天自己推进一件事（自主执行）

**背景**：不想每次都被"你来找我"驱动。

**做法**
1. 打开 `记忆/运行时/自主执行.json`，确认 `enabled: true`，范围是 `workspaceWrite / shell / localGit / build`
2. 让她用 `time_task` 注册一个每日任务（如每天 20:00 检查一件事并推进到下一步）
3. 每次自主动手都会出现在 `文档/自主执行审计.md`

**产出在哪**：`文档/时间引擎日志.md`（每次结果）、`文档/自主执行审计.md`（每次动手）

**边界**：出图出片、对外发布仍然要人点头；她不能改自己的权限。
