# 平台注入检测教程（中转平台防骗指南）

> 背景：2026-10-10，可乐平台（kele520.com）与 code28（code28.ccwu.cc）被定性欺骗并从模型库删除。
> 它们的套路：用「实时注入」伪装成官方模型通道。本教程讲怎么识别，以及元枢的自动防线。

## 一、什么是「实时注入」欺骗

正常中转平台：你请求 `claude-sonnet-4-5`，它转发给真正的上游，返回真模型的输出。

注入型骗局平台：
- **编造模型目录**：返回 `claude-opus-5-5`、`claude-fable-5` 等官方根本不存在的型号，制造"模型很全"的假象
- **偷换通道**：你请求贵模型，它实际用便宜模型（甚至脚本）生成回复，`response.model` 字段与你请求的不一致
- **超长令牌**：发给你几万字符的"API Key"，本质是注入代理的路由凭证，平台可以随时改你看到的一切
- **实时变目录**：每次拉 `/v1/models` 返回的列表都不一样，模型数虚高（几百个）

## 二、六步检测法（拿到新平台先做再交钱）

### 1. 查域名
- 官方 API 都是知名域：`api.stepfun.com`、`api.deepseek.com`、`open.bigmodel.cn`
- 可疑信号：杂牌短域名（`kele520.com`、`*.ccwu.cc`）、刚注册的域名、套 CDNs 的中转域

### 2. 量 Key 长度
```bash
echo -n "你的APIKey" | wc -c
```
- 正常 API Key：30~200 字符
- **超过 10000 字符 = 直接拉黑**（元枢已自动拒绝，见第四节）

### 3. 拉模型目录数模型
```bash
curl -s https://平台地址/v1/models -H "Authorization: Bearer 你的Key" | python -m json.tool | grep '"id"' | wc -l
```
- 单一厂商的官方 API：几个到几十个模型
- 一个"中转"号称几百个模型、还全是各厂旗舰 = 强烈可疑

### 4. 找编造的型号名
把目录里的模型名和官方发布列表对一遍。重点识别：
- 版本号跳水的（官方没有 opus-5-5 / sonnet-5-5）
- 官方从未发布过的产品线（`fable`、`luna` 之类花哨名）
- 真型号 + 假后缀（`claude-4-5-20251101` 这种日期都是编的）

### 5. 实测对话，验「返回的 model 字段」
```bash
curl -s https://平台地址/v1/chat/completions \
  -H "Authorization: Bearer 你的Key" -H "Content-Type: application/json" \
  -d '{"model":"claude-sonnet-4-5","messages":[{"role":"user","content":"你是什么模型？你的版本号？"}]}' \
  | python -m json.tool
```
核对两点：
- `response.model` 是否等于你请求的模型（**被偷换 = 实锤**）
- 问它版本号，回答是否与你请求的一致

### 6. 探测服务是否内置（元枢用户专用）
- 系统页 → 模型 → 单模型「验证」按钮（走 `/api/models/verify`，直连实测）
- 探测存档：`C:/Users/xuexiaofeng/.pi/agent/models_probe_result.json`
  - `CHANNEL` = 通道被拦（如 Cloudflare 拦截，整个平台废）
  - `AUTH` = 403（key 无效或平台要实名）
  - `DOWN` = 模型下架
  - `EMPTY` = 返回空（推理模式或假通道）

## 三、定价常识（防骗速查）

| 信号 | 判断 |
|---|---|
| 免费/1折用 claude-opus、gpt 旗舰 | 假（成本摆在那，只能靠偷换或脚本） |
| 按"额度/积分"计费不给单价 | 可疑 |
| 支持的付款方式只有个人收款码 | 跑路预备 |

## 四、元枢的自动防线（2026-10-10 起，同日加严）

> 背景：这类站上骗模型公司（拿免费/试算额度伪装多模型），下针对用户的检测做对策（偷换 model 字段、编造目录）。注入量 1000 token 以上的就该查。

添加平台（`POST /api/models/add`）时自动拦截，无需人工判断：

1. **超长 Key 防线**：API Key > 10000 字符 → 硬拒，报「疑似实时注入代理」
2. **目录分档防线**（按注入量 token 计）：
   - 目录 > 10000 token（约 40KB JSON）→ **硬拒**：实时注入目录疑似造假
   - 目录 1000~10000 token 或 > 60 个模型 → **不自动收录**，必须手动勾选具体模型（「该查」档：能用，但目录本身不可信）
   - 手动勾选模型的不受限（用户明确知道自己在加什么）

## 五、发现可疑平台的处置流程

1. 系统页 → 模型库 → 删除该平台（会同时清凭据）
2. 或手动双删：`C:/Users/xuexiaofeng/.pi/agent/models-store.json` + `auth.json` 里同名条目
3. 检查默认模型是否还指在已删平台上（`config.mjs` 的 `model` 字段）
4. 在群里/朋友圈提醒别人（骗局平台靠信息差存活）
