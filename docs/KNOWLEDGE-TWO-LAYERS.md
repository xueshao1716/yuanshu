# 知识的两层（2026-10-26）

## 第一层：给小语长经验（记忆）

入库 → 抽 claim（决定/偏好/教训/事实）→ 按价值定寿命（90/30/7 天）→ 被引用则续命。
抽不出的碎片标 `source_excerpt`，7 天后自己走掉——**不假装它是知识**。

已知短板：规则抽取对截断的对话文本效果一般（会抽出半句话）。要提升得用模型抽取，代价是调用费。

## 第二层：让元枢长能力（改代码）

不建在 prose 上，建在**结构化信号**上：

| 信号源 | 例子 |
|---|---|
| 外部崩溃回执 | 分发用户报回来的 `Timeout._onTimeout` 未捕获异常 ×20 |
| 卡死作业 | 知识作业卡在 `source_not_authorized` |
| 反复失败的作业 | 「小语宣传片 45s 重渲染」失败 5 次 |

每个提案必须四件套，缺一不算数：

- `evidence`：证据在哪（能被点回去）
- `area` + `test`：动哪块、用什么测
- `effect`：修了对谁有用
- `recurrence`：同类出现几次（参与打分）

生命周期：`proposed → accepted → shipped(version+commit+test) → verified`。
**`shipped` 不给 `test` 就 400**——这是「真进化」的底线。

## 为什么不用操作日志当信号源

试过：抽出「第二个坑」「根因还有一层」「| 补 |」这类半句话，污染提案列表。
结论：**宁可少一个来源，也不要有噪声**。真要利用日志，得先让日志写成结构化条目。
