# 主人确认收尾

已获用户授权实施；不代替本人完成 Windows 验证。延续培养中心视觉及现有权限边界。

## 设计

- 保留已有外部 Ed25519 签名路径。新默认路径为 Windows 桌面 Hello 注册及逐次确认，私钥留在验证器中。
- 首次注册只能通过受限桌面命令调用 Windows WebAuthn（platform + required UV），不接受调用者传入公钥、不提供 HTTP 注册接口。仅成功后以 create-new 写入当前用户本机应用目录下按工作区哈希分隔的公开凭据。
- 服务首次发现本机凭据时固定它；凭据丢失、损坏、替换后本进程锁定并撤销挑战，不能静默换主人。已配外部签名配置优先且不回退。
- 桌面只接受 main 窗口准确的 127.0.0.1:8787/localhost:8787 来源，固定 RP/origin。签名只接受服务挑战格式，核对完整操作哈希，验证器要求本人验证。返回 proof 自动提交；旧客户端、网页、未配置 Hello、取消和未知提交结果分别提示。
- 服务验签同时核查绑定凭据、RP、UV/UP、clientData challenge、origin、有效期及不可重放。访问令牌、localhost、调用者 actor 均不升格为主人身份。
- 注册不启用任何学习策略。界面提供七天、无外网、无付费请求、仅已核查培养经验的可审阅预设；执行仍需真实签名。保留暂停、撤销、现有审计。

## 实施与验收

1. 补安全回归及界面契约测试，确认红灯。
2. 实现 WebAuthn 验签、本机固定凭据和原生注册/确认，补正常及拒绝路径。
3. 收拢界面：就绪检查、范围摘要、自动提交、高级签名回退、失败恢复。
4. 隔离全量 verify、原生测试及构建、Impeccable 检查、桌面/窄屏 DOM 验收。
5. 保留主目录已有资产与主题改动，合并、发布、精确重启、双仓同步、安装包交付。
6. 读回真实策略。Hello 不可用时如实交付为等待本人启用验证，不声称自主学习已运行。

## 自审边界

本机可信文件属于宿主部署边界，不能抵御已能任意修改服务代码或用户文件的恶意本机进程。不得宣传为此类攻击下的硬件隔离；真正硬件持有的签名密钥不能由网页或模型导出。首次配对的人必须是设备主人，这不是远程身份认证服务。任何自动确认、静默替换或经 HTTP 写入可信文件的路径均不允许。
